## inspect

Take a reproducible snapshot of the connected Oracle schema — tables, columns, keys, indexes, views and sequences — and optionally compare it with declared tables to find drift. Choose this before loading or reporting, or to confirm that a deployed schema still matches its declaration. Two fresh connections must observe the same snapshot.

Common mistakes and assumptions:

- Declared tables are compared column by column and key by key; check constraints are compared by count only.
- Inspecting never changes the database.

Native binding: `USER_TABLES/USER_TAB_COLS/USER_CONSTRAINTS/USER_IND_COLUMNS/USER_VIEWS/USER_SEQUENCES queries`. Output kind: `["text"]`.

## load

Common mistakes and assumptions:

- CREATE TABLE commits implicitly in Oracle, so a failed load can leave created tables behind; the row import itself is atomic.
- Empty text is NULL in Oracle and is refused unless a column says emptyText is null.

## mutate

Run an atomic group of insert, update, delete and merge steps with savepoints and exact row-count expectations, then commit or roll back. A separate observer connection proves that uncommitted work is invisible and that the final state matches an independent simulation. External mutation requires the complete schema and refuses enabled triggers, virtual/default columns, function/domain indexes, row policies, REFERENCES grants and undeclared incoming cascading child tables before DML. Prospective assignment checks run before the first DML in the transaction snapshot, and native rows must match that reference before commit.

Common mistakes and assumptions:

- Any failing step or unmet expectRows rolls back the whole transaction.
- A COMMIT whose result cannot be read is reported as outcome unknown and is never replayed.

Native binding: `INSERT/UPDATE/DELETE/MERGE; SAVEPOINT; ROLLBACK TO; COMMIT/ROLLBACK; observer connection`. Output kind: `["table","text"]`.
