## applyTransform

Bakes the input object's world transform (location, rotation and scale from centre, cube size or transform) into the vertex coordinates of a copy and resets the object transform to identity. The world-space shape is unchanged, but later modifiers then act on world-sized geometry about the world origin. Insert it before bevel, solidify, voxelRemesh, bend, twist or mirror when their sizes, axes or planes must refer to world units.

Common mistakes and assumptions:

- It does not move anything visibly; compare modifier results with and without it when proportions look wrong.
- The adaptor's recorded native qualification cases cover only a material on a cube; this operation relies on repository examples, not on a recorded qualification case.

Native binding: `applyTransform`. Output kind: `["data"]`.

| `input` | one node | yes | `data` |

## array

Repeats the input mesh count times in one new mesh with Blender's Array modifier, each copy offset by relativeOffset times the input's bounding-box size along each local axis (relative offset on, constant offset and vertex merging off, as in a new Blender modifier). Use it for regular rows of blades, fins, bolts or test specimens.

Common mistakes and assumptions:

- count includes the original; count 1 produces no copies.
- Copies touching at relativeOffset 1 are not merged; add weld if they must be connected.
- The adaptor's recorded native qualification cases cover only a material on a cube; this operation relies on repository examples, not on a recorded qualification case.

Native binding: `array`. Output kind: `["data"]`.

## assignMaterial

Copies the evaluated input mesh (with its world transform) and replaces all of its material slots with the single material input on every face. The upstream object and its materials stay unchanged, so the same geometry can be styled differently for several presentations. Use it for imported or processed meshes, which have no material input of their own.

Common mistakes and assumptions:

- Per-face material assignments from join or imports are lost; every face gets this material.

Native binding: `assignMaterial`. Output kind: `["data"]`.

## bend

Bends a copy of the input mesh with Blender's Simple Deform modifier in Bend mode: the mesh is curved about the selected local axis by a total angle in radians spread over the mesh's extent. Other Simple Deform settings keep Blender's defaults (no origin object, full 0 to 1 limits), so the deformation is centred on the input object's local origin. Give the input enough vertices along the bend (subdivision method SIMPLE or grid) for a smooth curve.

Common mistakes and assumptions:

- angle is in radians, not degrees (1.5708 is a right-angle bend).
- A cube or plane has too few vertices to bend smoothly; subdivide first.
- Bending acts in local coordinates; bake transform scaling with applyTransform first when proportions matter.

Native binding: `bend`. Output kind: `["data"]`.

| --- | --- | --- | --- |
| `input` | one node | yes | `data` |

| Option | Meaning | Type / constraints | Default |
| --- | --- | --- | --- |

## bevel

Rounds or chamfers the edges of a copy of the input mesh with a Blender Bevel modifier (affect: edges) and produces a new mesh object with the input's world transform; the input object is unchanged. width and segments are assigned; the other Bevel settings keep Blender's new-modifier values, so width is the Offset of the new edges from the original edge and only edges whose faces meet more sharply than the 30 degree angle limit are bevelled. Follow it with shadeSmooth and weightedNormal for clean hard-surface shading.

Common mistakes and assumptions:

- width is in the input's local units; after cube or transform scaling the world bevel is larger or smaller. Use applyTransform before bevel to work in world units.
- Gently curved regions (faces meeting at less than 30 degrees) are not bevelled by the native angle limit.

Native binding: `bevel`. Output kind: `["data"]`.

| --- | --- | --- | --- |
| `input` | one node | yes | `data` |

| Option | Meaning | Type / constraints | Default |
| --- | --- | --- | --- |

## boolean

Combines the input mesh with a second mesh, the operand, using Blender's Boolean modifier with the Exact solver: DIFFERENCE cuts the operand away, UNION merges both volumes and INTERSECT keeps only the overlap. The result is a new mesh object; the operand is unchanged and is rendered only if listed as visible. Use it for holes, cut-aways and section views.

Common mistakes and assumptions:

- Both meshes should be closed, consistently oriented volumes; open sheets give unreliable results (solidify them first).
- Coplanar faces are handled by the Exact solver but are slow on dense meshes; offset the operand slightly when possible.
- The adaptor's recorded native qualification cases cover only a material on a cube; this operation relies on repository examples, not on a recorded qualification case.

Native binding: `boolean`. Output kind: `["data"]`.

| --- | --- | --- | --- |
| `input` | one node | yes | `data` |
| `operand` | one node | yes | `data` |

| Option | Meaning | Type / constraints | Default |

## cube

Creates a closed six-face cube mesh object with edge length size, centred on centre, using the material input. Schemaxis builds a fixed mesh spanning -1 to 1 on each local axis and realises size as the object's scale (size/2 on every axis) and centre as its location. Choose it for boxes, test parts and bevelled enclosures; for a non-cubic box follow it with transform scale, and use uvSphere, cylinder or the other primitives for other shapes.

Common mistakes and assumptions:

- Downstream modifiers (bevel width, solidify thickness, voxelSize, weld distance) act on the -1..1 local mesh, so they scale with size; insert applyTransform first when they must be in world units.
- This is the operation in the recorded native qualification cases (signed volume 8 for size 2 and 27 for size 3).

## curveFromCSV

Reads point coordinates from named columns of a numeric CSV table and sweeps the same round tube as polylineTube along them (rows in file order, 2 to 1024 rows). With zColumn empty the curve is planar at z = 0. The file is copied into the run directory and its SHA-256 digest is checked, so a measured or simulated trajectory becomes a reproducible presentation mesh.

Common mistakes and assumptions:

- Every cell of the CSV, including unused columns, must be a finite number under a UTF-8 header row; text columns fail with INVALID_TABLE.
- Coordinates are used as Blender units without conversion; rescale with transform if the table is in millimetres.
- The adaptor's recorded native qualification cases cover only a material on a cube; this operation relies on repository examples, not on a recorded qualification case.

## material

Creates a Blender material whose Principled BSDF shader inputs are set from the options: colour drives Base Color and Alpha, and the other options drive Roughness, Metallic, IOR, Transmission Weight, Coat Weight, Coat Roughness, Emission Color and Emission Strength. It produces a material resource, not geometry: every primitive needs one through its material input, and assignMaterial applies one to any processed or imported mesh. Every option has a Schemaxis default that is always assigned and read back from the shader, so an empty options object gives a mid-rough, non-metallic blue surface.

Common mistakes and assumptions:

- A material cannot be listed in a scene's visible or meshes; list the mesh that uses it.

- voxelSize is in the input's local units; on a scaled object (cube size, transform scale) the world voxel size differs. Use applyTransform first.
- The input should enclose a volume; open sheets produce thin or unexpected shells.
- Topology, vertex count and fine detail change; do not use the result for dimensional checks finer than the voxel size.

Native binding: `voxelRemesh`. Output kind: `["data"]`.

| --- | --- | --- | --- |
| `input` | one node | yes | `data` |

| --- | --- | --- | --- |
| `voxelSize` | Edge length of the voxels used to rebuild the surface (Blender voxel_size, object space). ## weightedNormal

Recomputes the shading normals of a copy of the input mesh with Blender's Weighted Normal modifier (native face area weighting), so large flat faces stay visually flat next to small bevel faces. It changes only the normals used for shading and rendering; vertex positions and topology are unchanged. Typical chain: bevel, shadeSmooth, weightedNormal.

Common mistakes and assumptions:

- STL mesh publications discard normals, so the effect appears only in rendered images and the saved scene.
- This operation does not repair topology or holes.
- The adaptor's recorded native qualification cases cover only a material on a cube; this operation relies on repository examples, not on a recorded qualification case.

Native binding: `weightedNormal`. Output kind: `["data"]`.

| Input port | Multiplicity | Required | Kind |
| --- | --- | --- | --- |
| `input` | one node | yes | `data` |

| Option | Meaning | Type / constraints | Default |
| --- | --- | --- | --- |
| `weight` | Bias between faces when averaging vertex normals: 50 is neutral; higher values let large faces dominate more strongly, lower values give small faces more influence. | `{"type":"integer","minimum":1,"maximum":100}` | `50` |
| `keepSharp` | When true, edges marked sharp keep separate normals on each side, so hard edges stay crisp; when false each vertex gets one weighted normal. | `{"type":"boolean"}` | `true` |


## weld

Merges vertices of a copy of the input mesh that lie closer than distance, using Blender's Weld modifier in its default All mode. Use it after join, imports or array copies to fuse coincident seams so the surface becomes connected (important before solidify, smooth or STL publication of a watertight part). It removes duplicate vertices only; it does not fill gaps wider than distance.

Common mistakes and assumptions:

- distance is in the input's local units; a value close to real feature sizes collapses small details.
- The adaptor's recorded native qualification cases cover only a material on a cube; this operation relies on repository examples, not on a recorded qualification case.

Native binding: `weld`. Output kind: `["data"]`.

| Input port | Multiplicity | Required | Kind |
| --- | --- | --- | --- |
| `input` | one node | yes | `data` |

| Option | Meaning | Type / constraints | Default |
| --- | --- | --- | --- |
| `distance` | Vertices closer together than this are merged into one (Blender merge_threshold). Choose it smaller than the smallest real edge but larger than the numeric gaps between coincident copies, for example 0.001 after join. | `{"type":"number","minimum":0,"exclusiveMinimum":true}` | `0.0001` |


## wireframe

Turns every edge of a copy of the input mesh into a solid strut of the given thickness using Blender's Wireframe modifier; replace removes the original faces and boundary also builds struts along open edges. Use it to show a mesh's tessellation or to create lattice-like presentation geometry; triangulate first for a triangle cage.

Common mistakes and assumptions:

- A triangle wireframe shows tessellation, not physical structure such as flow features.
- thickness is in the input's local units and is scaled by the input object's transform.

Native binding: `wireframe`. Output kind: `["data"]`.

| Input port | Multiplicity | Required | Kind |
| --- | --- | --- | --- |
| `input` | one node | yes | `data` |

| Option | Meaning | Type / constraints | Default |
| --- | --- | --- | --- |
| `thickness` | Thickness of the struts that replace each edge (Blender's Wireframe thickness, evenly offset by default). | `{"type":"number","minimum":0,"exclusiveMinimum":true}` | `0.02` |
| `offset` | Where the struts sit relative to the original surface: 0 centres them on the original edges, while values towards -1 or +1 shift them inside or outside the mesh (sides are decided by the face normals). | `{"type":"number","minimum":-1,"maximum":1}` | `0` |
| `replace` | When true only the struts remain; when false the original faces are kept as well, giving a surface with raised edges. | `{"type":"boolean"}` | `true` |
| `boundary` | When true, open boundary edges (for example the rim of a cut or a sheet) also get struts; when false they are left without. Closed meshes are unaffected. | `{"type":"boolean"}` | `true` |
