## scheduleWalls

Build a schedule of the plain IfcWall occurrences in one small ASCII IFC4 file: one row per wall, linked by GlobalId, with the property-set values and quantities you name. Each cell records whether it came from the occurrence, the wall type or nowhere, and quantities are converted from the project SI unit to metres, square metres or cubic metres. IfcOpenShell reads the file in its own process twice, and an independent standard-library STEP reader decides every GUID, origin and value; the published typed CSV and JSON schedule are rebuilt from that checked result, so a Calc workbook can be made from the CSV. Use it to reconcile what a model says about walls; it does not compute geometry, certify the model or validate the whole IFC file, and the schedule is a draft for BIM coordination review. IFC2X3, IFC4X3, Unicode escapes, subtype walls, lists and enumerations are refused rather than guessed.

Common mistakes and assumptions:

- Rows are plain IfcWall occurrences sorted by GlobalId; the Name is nullable literal text and never an identity.
- occurrence-only never reads the wall type; occurrence-overrides-type reads the type property set only where the occurrence has no such property, and each cell records occurrence, type or missing.
- Quantities come from the occurrence IfcElementQuantity only and are converted exactly from the project SI unit to m, m2 or m3; no geometry is calculated and nothing certifies the stored quantity.
- The typed CSV uses the null token \N and can be read by Calc readTypedCSV; each numeric column needs at least two present values there.

Native binding: `python -I worker.py source.ifc intent.json native.json (ifcopenshell.open, by_type, util.element.get_pset(should_inherit=False), get_type, util.unit.calculate_unit_scale)`. Output kind: `["table","text"]`.

Inputs: none.
