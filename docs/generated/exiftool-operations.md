## applySidecar

Apply the information in each photo's XMP sidecar to a new copy of the photo: the same typed transfer as copyMetadata with the sidecar as the source. The sidecar is captured, hashed and anchored, never modified and never copied; an item without one is reported and the others continue.

Common mistakes and assumptions:

- Only the values the sidecar actually records are applied; absent in the sidecar is a decision of the absent policy, never a guess. Existing sidecars are never merged or edited.
- ExifTool lists some sidecar properties it does not interpret (the altitude reference): the transfer reads them with Schemaxis's own reader.
- Without a sidecar for an item the item is reported and the others continue.

Native binding: `the same copy writer with the typed values of the item's XMP sidecar as source: one perl exiftool -config "" process per item, -GROUP:TAG=value assignments planned from the sidecar snapshot (never -tagsFromFile); -o stage/ID.jpg captured/ID.jpg`. Output kind: `["image","text"]`.

## auditMetadata

Audit the metadata of a media set against a closed rule set: required fields, conflicting or duplicated sources, malformed values, time plausibility (GPS UTC against the capture instant, digitization before capture), a privacy inventory of location, device and creator fields, and identical-content duplicates. Findings name the rule, item, field, state and evidence in audit.json and a typed findings.csv. It reports observations only: a clean audit is not certification, a finding is not proof of tampering, and nothing is changed or removed.

Common mistakes and assumptions:

- Findings are about recorded metadata, not about the photographed event.
- privacyInventory lists what a file carries so you can decide; it does not make a file safe to share.
- requiredFields needs require; timePlausibility needs a recorded offset to compare GPS and capture times.
- Every audited field is read by the same independent decoders and anchored to ExifTool as inspectMetadata.

Native binding: `the same fixed native listing, used to anchor the independent reader; the audit itself is host logic over typed records`. Output kind: `["text","table"]`.

## compareMetadata

Compare the typed metadata of every item with one named baseline item, field by field: same, different, missing in the item, missing in the baseline, both absent or not comparable (ambiguous, unreadable or unsupported). Equality is exact on canonical values and nothing is rounded or preferred. differences.csv is a typed table for a workbook and comparison.json keeps each side's state and value.

Common mistakes and assumptions:

- Different is not wrong and same is not authentic; the baseline is only the reference you chose.
- Fields outside the selected profiles and fields are not compared.
- The baseline item must succeed; if it is faulted the run fails with INVALID_BASELINE.

Native binding: `the same fixed native listing, used to anchor the independent reader; the comparison itself is host logic over typed records`. Output kind: `["text","table"]`.

## copyMetadata

Carry selected kinds of information from a source onto new copies of JPEG, TIFF, DNG, PNG, WebP and HEIF photos as typed values (any item can be the source), with exact text and rational pairs, declared conflict, absence and loss policies, and independent readback, byte-identical image data, a native before/after diff and a source-versus-output proof for every copy. Nothing is copied as a block.

Common mistakes and assumptions:

- Selected typed values only: MakerNotes, unknown tags, thumbnails and XMP structures are not copied, and the capture time and location groups are carried through the E3 writers, alone or in any union with the other groups.
- A copy never creates an Exif block or ExifIFD; a destination without one is refused per item, because creating it would change what an untouched GPS-only height means.
- Device serial numbers identify physical equipment and are carried only when you select them.
- A destination container without an IPTC slot (PNG, WebP, HEIF) declares the loss iptcNotAvailableInContainer instead of creating a carrier, and a HEIF destination without the needed Exif or XMP item is refused.

Native binding: `one perl exiftool -config "" process per item (the E2 copy writer): -GROUP:TAG=value assignments planned from typed values of an independent snapshot of the source (never -tagsFromFile, never a block or MakerNote copy, never authored as tags); -o stage/ID.jpg captured/ID.jpg`. ## correctTime

Write new copies (of the same container: JPEG, TIFF, DNG, PNG, WebP or HEIF with existing items) whose capture times are corrected by declared domain intent: a shift per camera clock group (days, hours, minutes and exact seconds), a skew derived from your true reference times, or a UTC offset with a keep rule (the instant or the wall clock). Every present EXIF, XMP and IPTC time of the selected fields moves together, proved by independent readback, byte-identical image data and a native before/after diff.

Common mistakes and assumptions:

- A correction is only as good as your declaration: references, assumed offsets and assumed-correct groups are not verified, and a corrected-looking time is not proof the clock was right.
- GPS time stamps are the receiver's clock and are never shifted; maker-note, preview, sidecar and file-system times are neither read nor changed (see residual.json).
- Selecting modified times moves a time that records an edit, not a capture; it is opt-in. Sources that disagree are refused by default.
- A photo outside every correction group keeps its artifact slot as an unchanged copy or an outcome document, by policy; check each item's outcome, because a run can be partly successful.
- Sub-seconds that IPTC cannot hold are truncated toward the earlier second and listed per item.
- In TIFF and DNG the IPTC time pair is rewritten too; PNG, WebP and HEIF have no IPTC. A HEIF file whose Exif item does not exist is refused, not given one.

Native binding: `one perl exiftool -config "" -n process per item: -GROUP:TAG=value assignments of every present time source (EXIF, XMP, IPTC), values computed by exact host arithmetic from declared corrections (never authored); -o stage/ID.jpg captured/ID.jpg. The clock model is host logic; no native time shifting, AllDates or expression is used`. Output kind: `["image","text"]`.

## editMetadata

Write new copies of photographs (a new copy of the same container: JPEG, TIFF, DNG, PNG, WebP or HEIF with existing Exif and XMP items) with their title, description, keywords, creator list, copyright, rights URL, rating, city or country set, cleared or (for keywords) added to and removed from. Items that cannot be written are refused or fail individually with an outcome document at their stable artifact slot.

Common mistakes and assumptions:

- Not a way to write raw ExifTool tags: only the nine catalogue fields can be edited, by intent (set, clear, add, remove).

- An existing IPTC character set is never changed over text it would reinterpret; legacy Latin-1 text keeps its meaning and the IPTC form of the edited field is removed and reported instead.
- Proof P is about bytes, not pixels: it says nothing about image authenticity, provenance or how a program renders the picture.
- Artifact slot i is the i-th item: a refused item keeps its slot as an outcome document (never an image), so binding that index to an image consumer fails instead of selecting another photo.

## locate

Common mistakes and assumptions:
