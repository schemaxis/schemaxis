## decodeToPng

Decode one captured static WebP back to a PNG that reports, documents and other tools can use. The adaptor captures the WebP once, reads its RIFF framing (exactly one VP8L chunk, or one opaque VP8 chunk), decodes it with the trusted libwebp dwebp (-nodither -pam), writes the samples as a canonical 8-bit RGB or RGBA PNG (only IHDR, IDAT and IEND), and decodes the captured bytes again to prove that every red, green, blue and alpha sample of the PNG equals the decoder output, including colour hidden under fully transparent pixels. Only dwebp is needed, not cwebp. Choose it to turn an existing web asset into a report-compatible PNG.

Common mistakes and assumptions:

- Only static simple-format files are accepted: animated, extended (VP8X with ALPH alpha, ICC, EXIF or XMP), multi-chunk and trailing-byte files are refused before any decoder runs.
- A lossy WebP decodes to what libwebp produces, not to the original picture; another decoder or viewer may differ slightly. Lossless input decodes exactly.
- The PNG is untagged (read it as sRGB, the web convention) and carries no text, EXIF or profile chunk. Its file digest depends on the host zlib; its samples do not.
- Verification re-decodes the captured WebP with dwebp and so needs that trusted decoder (SCHEMAXIS_DWEBP or a stored location); it does not authenticate where the WebP came from or re-read the original path.

Native binding: `dwebp captured.webp -nodither -pam -o decoded.pam (libwebp 1.6; one simple VP8L or opaque VP8 chunk); the host writes the canonical PNG`. Output kind: `["image","text"]`.

Inputs: none.

| `source` | Choose an absolute local .png file: a non-interlaced 8-bit RGB or RGBA image, untagged or tagged sRGB, at most 2048 pixels per side, 1,048,576 pixels and 8 MiB. ## encodeLossless

Publish one captured PNG as a lossless WebP for web pages. The adaptor decodes the PNG, encodes it with libwebp (cwebp -lossless -exact), then decodes the published bytes again with a separate dwebp process and proves that every red, green, blue and alpha sample matches the source, including colour hidden under fully transparent pixels. Choose it to reuse illustrations or transparent assets on the web without any pixel change. File size savings depend on content; no detail is discarded.

Common mistakes and assumptions:

- Lossless WebP is not guaranteed to be smaller than the PNG; check the byte counts in webp-summary.json.
- Only static non-interlaced 8-bit RGB/RGBA sRGB PNGs within 2048 pixels per side and 1,048,576 pixels are accepted; others are refused, not converted.
- A run needs both cwebp and dwebp; verification needs only dwebp because no host WebP decoder exists. The --dwebp flag applies to run; schemaxis verify takes SCHEMAXIS_DWEBP or a stored dwebp location.

Native binding: `cwebp -lossless -exact -z 6 INPUT.pam -o image.webp; dwebp image.webp -pam -o reopened.pam (libwebp 1.6; VP8L)`. Output kind: `["image","text"]`.

## encodeLossy

Publish one opaque captured PNG as a lossy WebP (VP8) for web pages where a photograph-like image may trade a bounded amount of accuracy for size. You choose cwebp quality (0-100, a lossy setting: 100 is not lossless), a mean-absolute-RGB-error budget and optionally a byte budget. The adaptor encodes with libwebp, decodes the published bytes again with a separate dwebp process, compares every red, green and blue sample with the source and publishes only if the measured mean error and the file size are inside your budgets. Otherwise the run fails with DELIVERABLE_NOT_MET and says what was measured. There is no automatic quality search.

Common mistakes and assumptions:

- Every pixel must be opaque (alpha 255). Any alpha value below 255 is refused with WEBP_ALPHA_UNSUPPORTED: use encodeLossless to preserve alpha, or flatten onto a background first.
- The error is the mean absolute difference over all width*height*3 RGB samples against the trusted dwebp default decode. It is not a perceptual score and does not describe other decoders or viewers; a small mean can hide a few badly damaged edges.
- A lossy WebP is not guaranteed smaller than the PNG. Flat charts, line art and screenshots often come out larger and less accurate than lossless; check the byte counts and error in webp-summary.json.
- A budget of 0 can only be met by a bit-identical decode, which lossy coding practically never gives; it is accepted as a legitimate way to refuse.

Native binding: `cwebp -q QUALITY -m 6 -alpha_q 100 INPUT.pam -o image.webp; dwebp image.webp -pam -o reopened.pam (libwebp 1.6; opaque VP8)`. Output kind: `["image","text"]`.
