## decodePCM16

Turn one native FLAC recording into a PCM16 WAV so it can enter speech preparation (SoX conform, then transcription). The host checks STREAMINFO, the metadata framing and the first frame header before anything runs, the trusted flac decodes the frames, and the decoded samples must match the FLAC's own sample count and MD5. Choose it when a recording arrives as FLAC; it does not repair damaged files, resample or change channels.

Common mistakes and assumptions:

- Only native FLAC that starts with fLaC is accepted: Ogg FLAC, ID3-prefixed files, 24-bit, more than two channels, an unknown (zero) sample count or an all-zero MD5 are refused with a distinct fault.
- Damaged frames are refused, never concealed. A matching MD5 proves the file is internally consistent, not that the recording is authentic or unaltered.
- Tags (including title, artist and description labels from an archive), pictures, seek tables and padding are dropped and listed, and no labels can be authored here; the WAV is 44 bytes of header plus PCM and at most 32 MiB, the largest file SoX conform accepts.

Native binding: `flac -d -s -w --no-preserve-modtime --force-raw-format --endian=little --sign=signed -o decoded.pcm captured.flac (FLAC 1.5); host wraps the PCM in a canonical 44-byte WAV`. Output kind: `["file","text"]`.

Inputs: none.

| `source` | Choose one absolute local file: a PCM16 mono or stereo .wav for encodeLossless, a native .flac for decodePCM16, at most 600 seconds of 8000-192000 Hz audio. ## encodeLossless

Archive one captured PCM16 WAV recording as native lossless FLAC. The host reads the WAV itself, hands the trusted flac only raw 16-bit PCM, and then decodes the published FLAC again in a separate process: every PCM byte must equal the WAV samples and match the FLAC sample count and MD5. Choose it to store a finished or intermediate recording in a smaller file without changing a single sample; it does not edit, resample or normalise audio. Optionally it stores a title, an artist and a description you wrote as native Vorbis comments, so an archive keeps its name with its audio; the host reads the published comment back and requires exactly those labels.

Common mistakes and assumptions:

- Only canonical PCM16 mono or stereo WAV at 8000-192000 Hz, at most 600 seconds and 32 MiB, is accepted; 24-bit, float, multichannel and compressed WAV are refused, not converted.
- WAV LIST and JUNK chunks are dropped and listed in the summary; without metadata the FLAC carries no tags, and it never carries pictures or cue points. The file is not guaranteed to be smaller than the WAV (noise barely compresses).
- A run and a later verification both need the trusted flac (--flac for run, or SCHEMAXIS_FLAC or a stored flac location); verification can never succeed without it.
- metadata labels are author-declared text, not an identity, rights or provenance certificate; they are stored exactly as written (no trimming or Unicode normalisation), must be nonempty visible plain text, and are dropped again by decodePCM16.

Native binding: `flac -8 -V -s -w --no-padding --no-seektable --no-preserve-modtime --force-raw-format --endian=little --sign=signed --channels=N --bps=16 --sample-rate=R -o audio.flac source.pcm (with authored metadata labels also: --no-utf8-convert --tag=TITLE=T --tag=ARTIST=A --tag=DESCRIPTION=D, fixed order, one argument per value); flac -d -s -w --no-preserve-modtime --force-raw-format --endian=little --sign=signed -o reopened.pcm audio.flac (FLAC 1.5)`. Output kind: `["file","text"]`.

Inputs: none.
