# SoX speech conform: completion review

Scope: the new `conform` operation of the `schemaxis.sox/1` route. The `assemble`
operation, its effective plan, schema branch, launchers, receipts and limitations are
unchanged and keep their earlier reviews (see the 2026-10-17 completion, the
2026-10-24 audio-preparation and the 2026-10-24 allocation notes). Native runtime:
SoX 14.4.2, the latest stable release on the official SourceForge list, rechecked on
24 October 2026. `absorbedVersion` is unchanged.

## Gap and decision

whisper.cpp accepts only PCM16 mono 16000 Hz WAV, while `assemble` accepts PCM16
mono/stereo 8000–192000 Hz and refuses resampling and channel conversion. A normal
44.1 or 48 kHz stereo recording therefore could not reach transcription. `conform`
adds a named, bounded conversion with explicit losses. This is product judgement from
the inspected gap, not demonstrated customer demand.

## Behaviour

- Fields: `source` (absolute `.wav`, the same contract as a clip source, so file
  artifact handoff works) and required `channelPolicy` (`average`, `left`, `right`).
- Mono sources accept `average` and `left`; `right` is refused (`AUDIO_CHANNEL_POLICY`).
- Fixed chain: `sox -D --single-threaded … remix {-|1|2} rate -v 16000`; no dither,
  gain, normalisation or authored options.
- Budgets: source <=32 MiB and <=600 s; native output file limit 24 MiB. The host never
  builds a sample list; it streams 65536-frame arrays.

## Native observations that fixed the verification rule

| Observation (SoX 14.4.2) | Rule adopted |
| --- | --- |
| 200049 random/extreme stereo pairs at 16 kHz: `remix 1,2` equals `(L+R+1)>>1`; left/right exact copies. `remix 1,2` and `remix 2` fail on mono. | Exact integer rule; mono uses `remix -` (documented mix-down) or `remix 1`. |
| 345 combinations of 15 rates and 23 lengths, odd and non-integer ratios, 0-frame outputs for tiny sources. | Frame count is round-half-up(frames*16000/rate); sources yielding 0 frames are refused. |
| Output phase offset zero at every probed rate. | Output keeps the recording time axis. |
| Full-band noise and square waves trigger SoX clipping warnings. | Saturated samples and warnings are counted and reported; stderr may hold only those two warnings. |
| Superseded: a full-band windowed-sinc reference refused correct native output for 48 kHz tones at 7600-9000 Hz (SoX transition differs legitimately; see the repair below). | Band-limited projection comparison (below). |
| 32 MiB sources: SoX <=0.31 s and about 4 MB; host verification about 2 s. | The 32 MiB / 600 s budget stands. |

A defect found by native smoke testing (an energy-sum loudness bound rejected 8 kHz
mono upsampling) is fixed with a mean-square bound and has a fail-before test.

## Verification limit (declared)

Same-rate conversion is recomputed sample for sample. Resampled output is **not**
recomputed, and individual resampled samples are not certified. With N the lower
Nyquist frequency, one independent physical-time low-pass (Kaiser-windowed sinc, unit
gain to 0.6 N, a nominal 100 dB design attenuation target from 0.8 N) is applied to the mixed
source and to the native output, and the two are compared at up to 512 interior instants.
Per instant the limit is half the output kernel L1 norm (rounding) + 1 LSB + 0.004 x
source peak (composite leakage of two linear-phase low-passes, with margin). Not
verified: content above 0.6 N (SoX's transition and stop band), the first and last
rate-dependent edge margins, sources without any eligible interior instant (`FIDELITY_NOT_SAMPLED`), and instants touching saturation
when SoX reported clipping (counted). A native replay alone is not treated as evidence.

### Repair: transition-band false corruption (2026-10-25)

A native stress probe found that correct SoX 14.4.2 `rate -v` output for 0.2 s 48 kHz mono
tones at 7600, 7700, 7800, 7900, 8000 and 9000 Hz (amplitude 10000) was refused as
`VERIFICATION_FAILED`. The full-band reference and SoX differ legitimately near the
output Nyquist frequency, and no beta/pass-fraction choice removes that. Reproduced
before the repair on the same native build. A wider probe also refused a 44.1 kHz
stereo mix containing 7800 Hz and an 11025 Hz source with a 5300 Hz tone (upsampled
transition). Additional serial acceptance probes, separate from the committed qualifier, found that all 23 cases verify (tones 200-12000 Hz,
chirp 50-23000 Hz, white noise at 8000/11025/22050/37813/44100/48000/192000 Hz,
full-scale clipping, short and edge sources). Native band residuals were under 0.7 LSB
in every case. SoX's gain was measured flat to 2e-5 from 1000 to 7000 Hz. Thirteen additional
mutation cases of real native output were refused (one-frame shift, 2% gain, polarity,
silence, zeroed block, three wrong-channel cases, upsampled shift, odd-rate gain, and
saturation without a native clipping warning). Two declared limits also pass: silence
replacing an output whose source lay only at 7800 Hz (`SILENT_OUTPUT` is raised), and
forged 7900 Hz energy added to a valid output.

## Native acceptance (serial, SoX 14.4.2, exit 0)

`PYTHONPATH=src python3 tools/qualify_sox.py --sox <SoX 14.4.2> --output-directory <fresh directory>`
ran the framework kit (nine cases, four new) and every earlier assemble check, then
independent conform oracles: analytic tones for 44.1 kHz average (max error 0.72 LSB),
48 kHz left and right (0.68 and 0.47 LSB; other channel 9493 LSB RMS away) and 8 kHz
mono (0.97 LSB); same-rate exactness for all three policies, plus 20081 random and
extreme pairs; 54 frame-count combinations; anti-phase and clipping flags; ten invalid
sources and four invalid documents, none launching native code; 23 forged native runs
with refreshed digests, all rejected; assemble-to-conform handoff, reuse invalidation
and a policy parameter study; repeatable output; a 32 MiB source in 9.3 s.
After the projection repair the conform acceptance (without the large case) was rerun
natively with seven new transition/out-of-band cases and two new forgeries per run
(one-frame shift, 2% gain): all passed. The 32 MiB case ran and verified in 9.4 s with
144 MB peak RSS and 512 compared instants.

## Limitations

Conversion covers only PCM16 mono/stereo to 16000 Hz mono with SoX 14.4.2 on the tested
build. No other rates, loudness changes, noise reduction, MPI or exhaustive native
coverage are claimed. Fidelity is a bounded band-limited check, not an oracle, and makes no general audio-accuracy claim. Shared generated
references and packaged Help drift until regenerated.

The fixed projection margin is a chosen acceptance limit, not a proved bound on every native filter response. Only the compared projected values are checked. Changes between sampled windows or below the peak-relative margin can be missed; a FIDELITY_NOT_SAMPLED warning means no waveform projection was checked.
