# whisper.cpp language admission

Route: `schemaxis.whispercpp/1`, `transcribe`. The `language` option accepted any `[a-z]{2,3}` string, so
`zz`, `zzz`, `qq` and `iw` planned successfully. Native `whisper_lang_id` refuses them only after the
audio and model have been captured and hashed and the process has been launched; `whisper-cli` then prints
`error: unknown language` and **exits 0 without writing results**. The host now refuses them first.
`absorbedVersion` stays `1.9.5`; no new ASR option, detection, `auto` or translation is added.

## Policy

| Item | Decision |
| --- | --- |
| Source | `g_lang` in whisper.cpp `v1.9.5` `src/whisper.cpp` (tag and commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`, the latest official release when checked; the file fetched from the official repository at that tag is byte-identical to the local checkout). 100 codes, ids 0 to 99. |
| Admission | Exactly one canonical lowercase code, as a string, from the static set in `languages.py`. Refused as `INVALID_LANGUAGE` at `$.language` with recovery text, before any other argument is validated and before any file, model, process or network use. |
| Refused | Unknown codes, full names (native `whisper_lang_id` would resolve `german`), uppercase (native lowercases `-l`; the receipt compares the exact plan language), `auto`, padding, `en-US`, empty, and every non-string including `null`, booleans, numbers, arrays and objects. Observed values are bounded. |
| Aliases | None are mapped. Upstream lists `he` (Hebrew; `iw` is not a code), `jw` and `yue`. |
| Meaning | Membership says only that this release knows the code. It does not certify that the selected model is multilingual (an English-only `.en` model ignores a non-English request) or recognition quality in that language. |
| Schema | `language` is an `enum` of the 100 codes with default `en`; guidance, capabilities, readiness and `docs/whispercpp.md` carry the same statement. |
| Unchanged | Plans, commands, losses and outputs for supported codes; existing `en` receipts; correction contracts, timed text and captions. |

## Newly run checks

* Before the change (new tests against the tree with only the admission edit reverted): 3 failures and 2
  errors of the 9 non-skipped tests, including `zz`/`zzz`/`qq`/`iw` accepted and wrong types located at
  `$.arguments.language` as `INVALID_ARGUMENT`.
* After: `tests/unit/test_whispercpp_languages.py` 10 tests pass (all 100 codes plan and reach `-l`
  unchanged; types, null, booleans, case, names, `auto`, padding; refusal precedes other arguments and uses no
  file, process or network; table equals the upstream table when `SCHEMAXIS_WHISPERCPP_SOURCE` points at a
  v1.9.5 checkout; schema, guidance, docs and readiness agree).
* Existing whisper.cpp host tests (`test_whispercpp`, `_segmentation`, `_corrections`) pass; Studio guidance
  and readiness audits for `whispercpp` are complete. The only failures in the wider affected set come from
  the incomplete `flac` manifest owned by another change, not from this one.
* Native, serial, bounded: `-l zz` is refused by `whisper-cli` with exit 0 and no output files; `-l en` with
  an English-only base model on the public 11 second sample produced one cue, language `en`. This is direct
  CLI observation, not Schemaxis route acceptance.
* Five existing genuine native receipts (English, caption review, excerpt, short cues, short cues with
  review) verify under a read-only mount with the new code; their bytes are unchanged.

## Limits

No multilingual model was run, so no non-English recognition is claimed. The code table is static: a future
whisper.cpp release that adds codes needs `languages.py` updated through the normal upstream update process.
Generated reference, packaged Help and `qualification.json` are not regenerated here.
