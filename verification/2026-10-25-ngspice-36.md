# ngspice reserved ground alias refusal — 2026-10-25

**Host-only change. No native ngspice executable was available, so nothing here is
native-qualified and no earlier native receipt was refreshed or invalidated by
observation.** Absorbed ngspice version remains 47.

## Defect and upstream basis

The planner treated the node name `gnd` as an ordinary node. ngspice lowercases the
deck and, unless `no_auto_gnd` is set, `inp_fix_gnd_name` in `src/frontend/inpcom.c`
replaces a whole `gnd` token (delimited by space, comma or parentheses, and not the
first token of a card) with node `0`. The generated netlist would therefore describe
a different circuit from the one the host predicted. The ngspice 47 tag
(release 47, 11 August 2026, current stable per the
[release news](https://ngspice.sourceforge.io/news.html)) and current master contain
an identical `inp_fix_gnd_name`; it writes ` 0 `, node 0.

Reproduced before repair with a divider whose lower resistor ends at `gnd` and a
third resistor from `gnd` to `0`: planning succeeded with nodes `gnd, in, mid`.

## Change

`plan()` now refuses the alias, matched case-insensitively, before any other
circuit analysis. Every authored node position is inspected in authored order:
source, resistor, capacitor and inductor terminals `a`/`b`, and probes. The fault is
`INVALID_CIRCUIT` at the exact location (for example `$.circuit.resistors[1].b`)
with the offending node, and recovery: use `0` for ground or choose another name.
Topology is never normalised. Valid input plans and exports identical netlists:
`gnd1`, `ground`, `agnd`, `gnd_a` and `gnda` remain valid (not rewritten, since
the native rule needs a whole delimited token), and a component named `gnd` is the
first card token, which ngspice does not rewrite.

Previously `GND`/`Gnd` were refused only by the generic lowercase-name check without
a location. They now receive the specific located fault.

## Legacy receipts

`verify()` replans the retained `authored.json`, so a receipt authored with `gnd`
now fails closed with the same located `INVALID_CIRCUIT` rather than a generic
verification failure. Whether any such receipt could ever have verified is not
established by observation. By source reading it could not have matched the raw-data
check: the generated `write result.raw` line holds the `gnd` token in `v(gnd)`, which
the rewrite replaces, so the native variable list cannot name `v(gnd)` while the
independent raw parser requires it. If the control lines were not rewritten, a table
could agree only when `gnd` was a zero-volt node whose merger with ground changes
no other voltage. No retained ngspice receipt was available to inspect. Genuine
circuits that do not use `gnd` are unaffected: all 11 plannable shipped ngspice
examples produce byte-identical plans and netlists before and after.

## Checks run (host)

- Fail-before: the new tests run against the previous `adaptor.py` fail (six
  failures: no fault for lowercase `gnd`, unlocated fault for case variants, wrong
  legacy-receipt fault, floating fault instead of reserved fault for a capacitor).
- `test_ngspice_admission.py` and `test_ngspice_performance.py`: 28 tests pass (18
  admission, 3 new: located refusal at all terminals/probes and four case variants,
  valid near-miss names with unchanged netlists, legacy-receipt verification).
- `studio_guidance.py --app ngspice --check`: 97 reviewed, 108 from references,
  0 pending, 0 stale. `readiness --app ngspice --admission --check` passes.
- A new readiness example, `reserved-ground-alias`, is a schema-valid invalid case.

## Not covered

No native ngspice 47 run of an unpatched `gnd` document was possible; the
mismatch rests on the retained official source rule. Other ngspice netlist
rewrites, such as KiCad-compatibility `/gnd`, are outside this circuit slice.
