# whisper.cpp allocation 54: host-only author-declared cue timing edits (`schemaxis.whispercpp.correct/3`)

Scope: the new separate route `schemaxis.whispercpp.correct/3` (`corrections_timing.py`) of the whisper.cpp provider, the new closed
output contract `schemaxis.timedtext.reviewed/3` in `schemaxis.core.timed_text`, and the Pandoc `transcript` block's provenance paragraph,
summary members and `transcriptObservations` entry for a reviewed/3 document. `correct/1`, `correct/2`, `reviewed/1`, `reviewed/2`, their
plans, publications and genuine receipts, the transcription route `schemaxis.whispercpp/1`, its official 1.9.5 mapping and its
qualification record are unchanged and are not re-reviewed here. This is a practical product judgement, not customer-demand evidence.
whisper.cpp 1.9.5, Pandoc 3.12.1 and package 0.4.0 are unchanged.

## Why a new protocol version

`correct/1` and `correct/2` explicitly promise the original machine timestamps, and `reviewed/1` and `reviewed/2` record nothing about
timing. Fixing a cue whose experimental token-level boundary is early or late by hand is ordinary caption-publishing work, but loosening the
old routes would reinterpret their promise. So timing edits are a new route, plan, ledger and reviewed contract; the old ones keep their exact
output; their closed documents already refused an unknown `timings` member (`UNKNOWN_ARGUMENT`), and still do.

## What the route does

- Document = the `correct/2` document plus `timings`: closed `[{index, startMs, endMs}]`, **original** source index, integer elapsed
  milliseconds, both ends of the final interval stated (no delta member). Floats, booleans and text are `INVALID_ARGUMENT`, never rounded.
  Plan-time (no file read): `TIMING_DUPLICATE`, `TIMING_DELETION_CONFLICT`, `TIMING_INTERVAL_INVALID` (start not before end),
  `CORRECTIONS_STATUS_CONFLICT`. Run-time: `TIMING_INDEX_INVALID`, `TIMING_NOOP`, `TIMING_OVERLAP`, `TIMING_AFTER_AUDIO`.
- The **finished** retained set is judged, not the edit order: each retained cue needs `0 <= start < end <= ceil(audio ms)` (the same bound the
  shared draft reader uses, now exposed as `timed_text.audio_limit`) and no cue may start before the previous retained cue ends. Touching
  intervals are valid; a cue may use time a deleted draft cue held. A refusal names the offending `$.timings[n]`. Nothing is clamped, reordered
  or rounded; cues are never added, split or merged; the audio, model and language never change. Reversed edit lists publish identical bytes.
- Status: `human-corrected` needs at least one replacement, deletion or timing edit (timing-only is `human-corrected`); `human-reviewed-unchanged`
  with `timings` is `CORRECTIONS_STATUS_CONFLICT`. All 512 cue, 256 character, 32768 total, 4MiB source, 500 character note limits remain; the
  total is judged on the finished text. Empty publication only by explicit deletion of every cue of a nonempty draft; `captionReview` is
  `CAPTION_REVIEW_EMPTY` then; an original zero-cue draft and a reviewed document used as a draft stay refused.
- `reviewed/3` review = every `reviewed/2` member plus `timingEditCount`, `timingEditedIndices`, `originalTimings` (original start/end of every
  retained cue by source index), `timingPolicy` and `synchronizationCertified: false`. The shared validator proves the edited indices are exactly the
  retained cues whose published interval differs from the recorded original, that originals are integral, ordered and inside the audio, and that the
  published times obey the shared rules. Ledger `corrections/3` uses `originalStartMs`/`originalEndMs` for the pinned draft's times and `startMs`/`endMs` for the published times in every section (`replacements`, `timingEdits`, `retained`); `deletions` carry only the original names because a deleted cue has no published time. It also adds `timingEdits` and a per-cue `retimed` flag. (Review 42 found the first version of this note's ledger used `startMs`/`endMs` for the original in `replacements`; that is corrected.)
- Every run and every verification replays all publications byte for byte from the captured draft bytes and the plan (replay, not signed authenticity).
  Host-only: planning reads no file, nothing launches or imports whisper-cli (a fake executable is never run; `subprocess` patched to fail in tests).
- Optional `captionReview` is recomputed from the published, edited durations; it still certifies nothing.
- Pandoc: the paragraph states how many cues were given author-edited start and end times (source indexes) and that the shown times for them are
  edited times recorded in this document as the author's, not the machine draft's, with the original machine times not shown; with no edit it says the
  author edited no times and the times shown are the draft's originals as recorded in this document (not checked against the draft file by Pandoc);
  with every cue deleted it shows no time. No machine-basis authentication is claimed. It never says timing was preserved and says synchronization is not verified or certified. The summary entry gains `sourceCues`, `deletedCues`,
  `timingEditedCues`, `timingEditedSourceIndices`; `transcriptObservations` gains a reviewed/3 entry. The plan's transcript-loss sentence is **not**
  rewritten, so stored plans keep verifying; legacy 45 deletion, 47 `timeFormat`, 50 physical ZIP and the one-cue grammar are untouched.

## Not claimed

- No reviewer identity, no proof audio was heard, no accuracy, readability, accessibility or **audio synchronization** certification, and no claim
  that an edited time is better aligned than the machine's. Every example/fixture note says it is an illustrative automated declaration and that no
  person listened to or reviewed the recording.
- **No native qualification of the correction route.** Host-only; no `qualification.json` entry. The native Pandoc run below is a *publishing handoff*
  check, not whisper.cpp requalification, and no new native CLI flag mapping exists, so no upstream re-check was needed and `upstream.json` is untouched.
- Not covered: splits, merges, insertions, offsets/stretching, importing an edited transcript, a second round on a reviewed document, audio edits.
- Retained-input limit as for `correct/1`/`correct/2`: workflow verification reopens the original `draft.path`; job-directory verification replays from
  `captured-draft.json`.
- Host Python is 3.14; the code avoids 3.12-only syntax, but no 3.10 runtime was run and none is claimed.
