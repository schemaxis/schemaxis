## Repairs after independent review r1 (written, not yet executed)

* Replace mode removed from the contract: a run never replaces or drops a table it did not create.
  Cleanup drops only tables the worker recorded as created in that run (and still marked), never
  after an unknown commit outcome; an in-flight failed CREATE is reported, not dropped.
* Credential handling: passwords and connect strings under eight characters are refused before any
  native work; the final status write is scanned; all leaking files are blanked; scanned forms include
  UTF-8/16, JSON, percent and base64; worker redaction covers whole values and never structured rows.
* Computed NUMBER results are decoded under a separate result policy (up to 80 digits) and compared at
  tolerance; stored NUMBER stays limited to 38 digits and exact. Range checks no longer depend on the
  ambient decimal context.
* Host tests keep the worker double patched for the whole action and forbid subprocess and network
  access; the qualification harness requires a named, confirmed schema and drops only tables that were
  absent when it started.
* The review's B1–B4/H1–H6 text could not be read by the authoring tools; each item must be checked
  against this list by the integration run.

## Repairs after independent review of 41f69f9 and root's r3 results (written, not yet executed)

* B3 assignment fit: update values are held to the target column. Literals are checked at planning; computed
  values are stored under Oracle's rule (38 significant digits, then scale/precision/length) in the reference.
  Scale and fractional-second loss is refused before any native work unless `scalePolicy: round`; precision
  (ORA-01438) and length (ORA-12899) overflow is predicted. A verification failure after the work finished now
  reports `databaseWorkCompleted`, the outcome and the retained tables.
* B2/result policy: computed NUMBER results use a 40-digit decoder (Oracle's computation width, observed
  natively), counted before any rounding and independent of the ambient context; the reference computes at 40
  digits; stored NUMBER stays 38 and exact.
* B4/H2/H3 ownership: every run binds its own marker; cleanup requires that marker, a worker-recorded
  CREATE, and is skipped after any unknown outcome (unknown commit, timeout, cancel). The worker journals
  every DDL and commit (synced before it runs), so a killed worker is reported from the journal. The seed
  commit is treated as ambiguous like the final commit. Database enforcement must match the predicted step
  and Oracle error number.
* H4/H5/H6: generated constraint names are no longer hidden; byte-semantics text is a distinct type; a read-only
  external use needs only the declared columns and keys; external rows and the report are read in one
  read-only transaction; native row order is verified against the declared order before ties are settled.
* Dates use a signed year mask for output and refuse BC years; `jsonNumber` now requires an exactly equal
  double; the qualification harness keeps the venv interpreter path, refuses to run under -O, and drops only
  tables that were absent when it started in a schema the operator named and confirmed.
* Pending from the review: run-unique physical scratch names or a scheduler exclusion (concurrent jobs
  staging the same logical table), an idempotency key for resumed retained loads, an SCN or timestamp in the
  snapshot record, anchoring receipts externally, and the wider native case list (set operations, distinct,
  offset, boolean/raw, CHECK/cascade/merge-ignore, concurrency, injected commit loss).

## Repairs after root's r4 results (written, not yet executed)

* Report snapshot: Oracle's `SET TRANSACTION READ ONLY` was observed natively to fail with ORA-01466
  immediately after DDL and the seed commit, so the report uses a query-only `SERIALIZABLE` transaction
  (observed natively to give a stable transaction-level snapshot while another session commits). The
  adaptor, not Oracle's READ ONLY mode, guarantees that nothing after the seed commit writes
  (`query_only` is applied to the generated program). External rows and the report share that snapshot.
  This engine observation is not adaptor qualification.
* Scratch tables use run-unique physical names (retained tables keep declared names); programs, results and
  evidence stay keyed by declared names and the dictionary snapshot is mapped back before drift checks.
* Tests: `comment_sql` takes the run marker; the seed commit is asserted to be flagged final.

## Known limits and decisions

* Doubles in the host tests are not an Oracle server; only `tools/qualify_oracle.py` against a live
  schema establishes server behaviour.
* The credential scan covers the password and connect string only (values of at least eight
  characters). The user name is session identity and is recorded in evidence by design.
* Mutation of pre-existing tables, negative/over-precision NUMBER scales, byte-aware longer text,
  identifier generalisation, subqueries and the families C12–C20 are pending; see the coverage map.
* Case conversion is verified for ASCII text only; Oracle and Python disagree for some Unicode text.
