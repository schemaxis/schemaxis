# Pandoc 50: optional EPUB 3 publication of the report route

Date: 25 October 2026. Route `schemaxis.pandoc/1`, operation `report`. Pandoc 3.12.1 (official self-contained build).

## Scope

An optional report-level `epub` object with one required field, `language` (plain ASCII tag: 2-3 letter primary
subtag and up to three hyphen subtags of 2-8 letters or digits, at most 35 characters), adds an EPUB 3 publication
written from the same trusted JSON AST as the HTML and DOCX files. Absent `epub` is absent: the plan, capture records,
summary, result, HTML, DOCX and artifact indices 0-2 are byte for byte what they were. Declared `epub` appends
`report.epub` as artifact index 3 (kind `file`); `epub-reopened.json` (a fresh `-fepub -tjson --sandbox` readback) is
retained evidence, not a publication. No Calibre or second runtime; no cover, fonts, metadata fields, filters, templates,
styles or native options are authorable. The report text/image budgets are unchanged; the package is refused, never
truncated, beyond 96 members, 32 MiB uncompressed, 8 MiB per XML/XHTML/CSS part and 4 MiB per image.

Native mapping: writer `-fjson -tepub3 --standalone --sandbox --metadata=lang:<validated> --output=report.epub
report-input.json`; reader `-fepub -tjson --sandbox --output=epub-reopened.json report.epub`. Public sources:
pandoc.org/epub.html and pandoc.org/MANUAL.html (opened 2026-10-25 by the coordinator; worker kept its own native probe).

## What is proved, and what is not

`src/schemaxis/adaptors/pandoc/epub.py` (host standard library only) independently reads the actual ZIP bytes (see the framing repair below): no prefix, suffix or hidden bytes; local headers equal their
central entries; a stored `mimetype` first at offset 0 with the exact bytes and no extra field; bounded, regular, unique, ASCII-safe member names (no
symlink, directory, encryption, backslash, absolute or parent path); a closed member set; pinned digests of the three
fixed writer parts (container, display options, stylesheet); the container rootfile; OPF identifier/title/language/date
and the writer's fixed metadata; manifest, spine, guide, navigation document and NCX cross-references; and XHTML chapters
(one per level 1 section) whose ordered headings, paragraphs, table cells and image elements equal the authored model
exactly, with PNG bodies compared by SHA-256, internal-only `../media/fileN.png` sources, explicit widths and alt text.
Scripts, external resources, DTDs and entities, comments, processing instructions, CDATA, SVG, fonts, inline styles and
changed stylesheets are refused; only the exact HTML5 doctype the writer emits is accepted. Pandoc's fresh EPUB reader
JSON is compared (title/language/identifier/date, file markers, section wrappers, headings, paragraphs, tables, images)
with the same model and the inspected media. The language is the author's declaration. This is a bounded package and
content proof: not EPUBCheck, not reading-system or device rendering, not accessibility conformance, not language
detection or accuracy. The coherent-forgery boundary is unchanged: the run directory is an unauthenticated trust anchor.

## Repair after review (25 October 2026): ZIP framing, media closure, wording

An independent read-only review found that the first attempt checked only the central directory. The repair keeps every proof above and adds:

- **M1, physical framing (fixed, not narrowed).** `epub.frame` reads the raw bytes: the file starts with a local header; the end record is the
  last 22 bytes with no comment, disk or ZIP64 field; the central directory ends exactly there; members tile the file from offset 0 to the
  central directory with no prefix, suffix, gap or hidden bytes; central order equals physical order; every local header repeats its central
  entry (version, flags, method, time, name, CRC-32, sizes; a lawful trailing data descriptor, with or without signature, may carry the last
  three) and has no extra field; central entries have no extra field, comment, disk or text attribute; deflate streams must be complete, exact
  and unpadded. The standard reader must agree with that framing. This is a conservative fixed Pandoc profile, not a general ZIP reader.
- **Independent byte-level tests.** `Framing` in `tests/unit/test_pandoc_epub.py` writes ZIP bytes with `struct` (its writer reproduces the
  genuine fixture byte for byte) and forges prefix, suffix, hidden bytes, reordered/listed-first central entries, local-versus-central
  mismatches of every field, mimetype extra fields, end-record fields, descriptors and deflate padding. Several of these archives are opened
  without complaint by `zipfile`, and run against the first-attempt `epub.py` they record 49 failures or errors (subtests counted; 12 of the 15 new tests fail there; the 48 earlier tests still pass).
- **L1.** Media membership is the set of member names the chapters actually reference (one file may serve several identical images); an
  unreferenced member, even with another image's bytes, is refused.
- **L2.** The guidance pitfall now states the real report budgets (32 sections, 128 blocks, 65536 characters, 8 images, 4 MiB each, 8 MiB
  combined); the package limits only guard against tampered or unexpected writer output.
- **L3.** The fixture docstring describes the real procedure (copy from a qualified run); no `--write-fixture` option exists.
- **L4.** Pandoc 3.12.1 preserves language case, so `EN` and `zh-hans-cn` now run in the native matrix (10 languages).
- **Wording.** 72 recorded processes in the first run were 25 direct probes with native PIDs and 47 adaptor stage submissions with the
  supervisor PID and reported exit code only. The repaired run records 78: 31 direct probes with native PIDs and the same 47 stage submissions.
- Newly run: Pandoc host tests 215 OK (1 skipped; 200 before, 15 added); 190 shared affected tests OK (1 skipped); guidance 34 reviewed, 0
  pending; admission 120 pass, 0 fail; native qualifier into a fresh directory passed with 45 refreshed-hash forgeries (30 earlier plus 15
  physical or media) refused as `VERIFICATION_FAILED`, the committed fixture equal to live output, and three earlier genuine runs re-verified unchanged.
  Not run: the full suite, generated references and Help, the release gate.

## Limits

tag grammar is checked, not validated against the IANA registry. The three-member fixed writer parts are pinned to Pandoc 3.12.1 digests; a
newer writer that changes them is refused until reviewed. Not run here: the full unit suite, global generators and release gate.
