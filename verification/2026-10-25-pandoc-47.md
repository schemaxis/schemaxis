# Pandoc transcript time format — 25 October 2026

Scope: the existing closed `schemaxis.pandoc/1` report route gains one optional field on the
`transcript` content block, `timeFormat` (`milliseconds` or `timecode`). It changes only how the cue
start and end times of a retained timed-text document are written in the published table and
provenance paragraph; it adds no native mapping, option or AST node. Earlier reviews:
[transcript block](2026-10-25-pandoc-33.md), [transcript](2026-10-24-pandoc-transcript.md),
[hostile evidence](2026-10-24-pandoc-evidence.md).

## Gap and decision

A transcript block always published `Start (ms)` / `End (ms)` as raw integer milliseconds. That is
useful for machine audit but harder for people reading a published transcript, who expect
`HH:MM:SS.mmm`. This was judged from the inspected output, not from stated customer demand. The
existing publisher is strengthened; no new adaptor.

- `timeFormat` absent: nothing changes. The field stays absent from the plan, captures, summary and
  result, and the publication is the same bytes as before. An explicit `milliseconds` publishes the
  same table and provenance paragraph and records the choice.
- `timecode`: every start and end is `HH:MM:SS.mmm` from integer division of the recorded
  milliseconds (no float, rounding or truncation; hours are not capped at two digits), under the headers
  `Start (HH:MM:SS.mmm)` / `End (HH:MM:SS.mmm)`. The provenance paragraph shows the audio duration in the
  same form and states the unit. Cue order, text, provenance, status, source rules and budgets are
  unchanged (the longer time text counts toward the existing 65536-character report budget).
- Any other value (boolean, number, null, another name) is refused at planning as `INVALID_ARGUMENT` at
  `<block>.timeFormat`, before any file read or native step.
- The explicit field is bound in `authored.json`, the plan (one extra loss sentence only when a block
  is `timecode`), the capture record (`timeFormat`), the report summary (`transcriptTimeFormats`, one entry per
  transcript block) and the verification result. `verify` recomputes the AST, expected model, HTML, DOCX and
  fresh readback from the retained captured bytes and the authored format.
- Each block chooses independently; two blocks over the same pinned source verify independently.
- Not changed: shared `timed_text`, registry/workflow guidance, generated reference/Help, README, the
  qualification record, versions, `absorbedVersion`, deletion semantics or any timed-text version.

## Limits

Reading format only: no recognition accuracy, timing accuracy, readability or accessibility claim, no wall-clock time and no caption
file. Layout and Word application behaviour are not exercised. Times beyond the audio bounds, overlaps and unsupported
cue text are still refused by the source contract. `schemaxis.timedtext.reviewed/2` empty-reviewed support and deletion semantics are not in this change.
