# Descriptive ParaView filenames and viewer properties

New ParaView publications use the documented `schemaxis.artifact-name/1` format.
Each primary publication reserves a run-wide six-digit ordinal before writing;
companions share its basename. Native bundle members retain their format layout.
Existing receipts and legacy viewer inference remain supported.

Checks run on Linux:

- 116 selected host tests passed: naming, viewer transport, shared adaptor/runtime,
  runtime archive/context, parallel handoffs, workflow resources and templates.
  This includes four-process allocation, continued/fresh/legacy runs, failed-write
  gaps, exhaustion, copied run contexts and the actual ParaView publication loop
  exercised through a mocked native boundary.
- 272 ParaView host tests completed successfully, with six native-dependent skips.
  Indexed writer payload names are checked against the authored scene/export;
  EnSight's native `.0.case` fallback retains the descriptive basename.
- 29 viewer model/browser tests passed with the generated and native fixtures enabled.
  Checks include Python/JavaScript codec agreement, intersecting/list filters,
  malformed names, import isolation, spatial/temporal sequence separation,
  metadata precedence, property-filter replacement/reset and actual MP4/WebM
  decoding and seeking in Chromium.
- The eight-publication native acceptance example plans successfully.
- Adaptor discovery, release scanning of tracked and changed/new files, and
  whitespace checks passed.

The mixed-media fixture is generated by `tools/generate_viewer_fixture.py`, rather
than committed as binary data. It contains synthetic content only. The viewer
remains independently runnable with no new runtime dependencies.

Native serial acceptance used ParaView 5.13.3 with its Python 3.10.13 runtime:

- The eight-publication example exported two datasets, two measurements and four
  images, with distinct ordinals `000000` through `000007` and eight verified
  companions. Both positions and both U/p variants retained checked slice planes.
- A two-operation workflow executed separate native processes and produced managed
  CSV exports numbered `000000` and `000001` across the operation boundary. Native
  readback, retained export evidence, workflow verification and companions passed.
- Chromium loaded the native exports without metadata warnings, grouped the two
  slice scenes into separate U/p sequences, decoded both U images and filtered by
  variable while retaining checked physical coordinates.

The native run exposed session-dependent defaults: the first curated Slice had
empty offsets, while later Slice instances had `[0]`. The curated single-plane
declaration now explicitly sets `SliceOffsetValues: [0]`. The general `pvSlice`
plane check remains conservative for empty, multiple and nonzero offsets. A host
regression and the repeated native example verify this correction.

Bulk receipts are retained locally under `evidence/output-filenames-native-2026-11-06`.
Full-repository unittest discovery was interrupted during broader adaptor tests;
it is not claimed as a passing full-suite result. No MPI qualification was run.
