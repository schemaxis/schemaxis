# eSpeak NG narration draft: new adaptor (2026-10-25)

Scope: the new `espeakng` adaptor, route `schemaxis.espeakng/1`, one operation `narrate`. It turns one captured
plain-text script (a literal `text` string or an absolute UTF-8 `.txt` `source` file or artifact, exactly one) into one
synthetic PCM16 mono 22050 Hz WAV (`narration.wav`) plus `espeakng-summary.json`, using the fixed eSpeak NG `en-us`
voice, pitch 50, amplitude 100 and an integer `rateWpm` of 120 to 240 (default 175). This note covers that operation
only. The output is a synthetic DRAFT for a human to review for words and sound. It is not a human recording and it
claims no intelligibility, pronunciation, accent or accessibility certification. No source-bound qualification receipt
is registered and `upstream.json` keeps `absorbedVersion` unset until the shared integration freezes.

## Practical value and decision

The existing adaptors prepare audio (SoX, FLAC), transcribe it (whisper.cpp) and publish text (Pandoc), but none can
create a voice-over draft. A small offline text-to-speech step complements creative publishing: text in, WAV out, which
then feeds `sox conform` or `flac` unchanged. This is a judgement from inspecting those adaptors, not customer-demand
evidence. The name `espeakng` was accepted as given and is documented in `docs/espeakng.md`. The adaptor is bounded
accordingly: one voice, no authored native flags, no SSML or phoneme input, no network, playback, language detection or
translation.

Budgets: at most 1024 Unicode code points and 8 KiB of UTF-8 in the captured text; at most 120 s and 8 MiB of WAV. The
duration cannot be computed from the text, so the budget is applied to the native output and a longer synthesis is
refused with `ESPEAKNG_BUDGET` and no publication.

## Verifier design

There is no host speech synthesizer and none is claimed. Verification **requires a trusted, separately configured
`espeak-ng`** (explicit argument, stored location `espeakng`, or `SCHEMAXIS_ESPEAKNG`) with the matching native data. It
is unavailable (`INTERPRETER_NOT_FOUND`) without it, never reports success offline and never searches `PATH` or launches
a receipt's executable. In a private temporary directory outside the submitted run it copies the captured script, runs
the same fixed `espeak-ng` stages in fresh bounded processes and compares **every PCM byte** plus sample count, rate and
channels against the published WAV. The canonical 44-byte-header WAV is rebuilt and compared independently with the
standard-library `wave` and `struct` modules. Retained JSON is read strictly (duplicate keys, non-finite numbers
including `1e400`, depth, and bool/int/float type changes are faults); `result.json` is a closed set of claims.

Determinism of re-synthesis was **observed only on the bounded cases below**, not proved. A different build, version or
native voice data can legitimately produce different samples and fail an old proof; the documented remedy is to verify
with the matching runtime and data or to record the narration again. The PCM comparison is never weakened.

## Limits

* Host tests use fakes of the native boundary except the one real-gated test and the native acceptance, which ran the
  real `espeak-ng`. Verification depends on the trusted `espeak-ng` and its data; it is not host-independent.
* One runtime was exercised: a private eSpeak NG 1.52.0 build on this host (Linux, Python 3.14). Python 3.10 to 3.13,
  other builds (with Sonic or MBROLA), other data versions and other releases were not run. The host-dependency-free
  Python 3.10+ and native-free planning claims were not run on 3.10 to 3.13.
* Determinism is observed on the bounded cases above; the 120 s and 8 MiB bounds were probed with repeated-token
  scripts and are enforced on the native output.
* The captured text is an unauthenticated trust anchor retained in the same writable publication directory. The output
  is a synthetic draft; there is no authenticity, intelligibility, pronunciation, accent or accessibility claim, and
  the voice is the requested `en-us` voice, not a certified accent.
* No source-current native qualification receipt is registered, the generated reference, packaged Help, installation
  guide and workflow guidance were not regenerated, there is no version bump, and the full suite was not run.
