# Pandoc 62: report authors and description metadata

Date: 25 October 2026 (America/Winnipeg; the evidence filename uses the UTC run date). Route `schemaxis.pandoc/1`, operation `report`. Pandoc 3.12.1
(official self-contained build). This is a reviewable implementation note, not an acceptance claim; the qualifier registered no receipt.

## Scope

One optional report-level `metadata` object: `authors` (1-8 distinct plain-text names of at most 100 characters, no semicolon) and
`description` (at most 1000 characters), published and read back consistently in standalone HTML, DOCX and optional EPUB 3. No other
key, markup, link, identifier or identity claim is accepted. Primary sources: Pandoc manual
[metadata variables](https://pandoc.org/MANUAL.html#metadata-variables) and [EPUB metadata](https://pandoc.org/MANUAL.html#epub-metadata).

## Native mapping observed (Pandoc 3.12.1)

JSON AST `meta.author` (MetaList of MetaInlines) and `meta.description` (MetaString). HTML: `author`/`description` meta elements and one
`<p class="author">` per author in the title-block header (description not in the body). DOCX: `dc:creator` joined with `; ` and
`dc:description` after it in `core.xml`, one `Author`-style paragraph per author after `Title`. EPUB: `dc:creator` with a
`marc:relators` `aut` refinement per author, then `dc:description`, and `p.author` lines on the title page; nav and NCX are unchanged.
Readbacks: the DOCX reader returns authors (a single author as MetaInlines, several as MetaList) and no description; the EPUB reader
returns authors in **reverse** order and the description. The verifier pins each observation and checks the package order independently.

## Contract decisions

- Plain text uses the report's existing rule (single spaces, no controls, no unsupported formatting characters). Empty or whitespace-only
  values, booleans, numbers, `null`, objects, an empty object and unknown keys are refused at the offending location.
- Order is kept. Exact duplicates are refused. A semicolon in an author is refused because Word stores a `; `-joined creator string.
- Authors and description count toward the 65536 character report budget. Characters, not bytes, are counted.
- Declarations only: no identity, authorship, accessibility, review or accuracy claim; a plan loss sentence says so.
- Absent field: plan, capture record, summary, result, commands, launchers, AST and artifact order are byte-identical (the existing
  pre-change fingerprints in `test_pandoc_epub.py` pass unchanged). Plan, document and summary versions are unchanged (additive optional
  member); an earlier Schemaxis refuses a report that declares it (`UNKNOWN_ARGUMENT`). No historical receipt was rewritten.
- Receipts: `captures.json` gains `metadata` (text, characters, SHA-256 of canonical JSON), `report-summary.json` gains `metadata`
  (counts and formats read back), the run result repeats it, all only when declared. Both are covered by the receipt's evidence digests.

## Native acceptance (`tools/qualify_pandoc_metadata.py`)

Run against the official 3.12.1 binary (SHA-256 `10a980df...ee1`, unchanged before and after). The multilingual fixture report with
three authors and a description (Unicode, `& < > " '`, a semicolon in the description) was run end to end; the retained HTML, DOCX and EPUB were
reopened with string/regex/zipfile literals only and equal the committed fixtures byte for byte. The same report without the field produced HTML,
DOCX, EPUB and both readbacks byte-identical to the committed earlier fixtures. Changed order, a changed name and a changed description each change
plan, capture and all three publications. A 14-case matrix (authors only, description only, single author, eight authors, 100-character author,
near-1000-character description, Unicode, each with and without EPUB) passed. 47 refreshed-hash forgeries across all formats, readbacks and receipt
files were refused (7 of them inject metadata into an earlier-style run). Thirteen invalid declarations were refused before any native launch, a workflow
resume reused an unchanged report, and a changed declaration did not resume (`RESUME_MISMATCH`). One genuine earlier retained run was re-verified read-only
with every byte unchanged. Three earlier qualifier attempts failed on assertions in the qualifier itself and are kept in the evidence directory.
