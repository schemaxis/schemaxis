# SoX two-track mix completion

The file name carries the allocation date; the work and every native run it records were done on 25 October 2026
(local time). Native timestamps in retained private evidence are UTC and may read as 26 October.

Scope: the new `mix` operation of `schemaxis.sox/1`: a narration and a background PCM16
recording, explicit per-track `gain` (0–4, at most four decimals) and `offsetFrames`, a required
`durationPolicy` (`longest` or `narration`), identical rate/channels required, clipping refused.
`assemble`, `conform` and `normalise` plans, commands, receipts and results are unchanged. Four
legacy assertions that encoded "exactly three operations" or used `mix` as the example of an
unknown operation were updated in `test_sox_conform.py` and `test_sox_normalise.py`; the behaviour
of the three older operations was not changed.

## Native semantics probed (SoX 14.4.2, serial)

`sox -m -v GA a -v GB b out` sums with per-input volume; without `-v`, SoX divides each input by the
input count, so the plan always passes both. `pad N 0` is an exact integer copy with leading silence
(`pad 0s 0` is an exact copy); `-m` pads the shorter input with trailing silence; `trim 0 Ns` after the
mix cuts to the narration end. SoX saturates a track after its own gain and warns on mix clipping, so the
host refuses both out-of-range terms and sums. Exact halves went toward positive infinity (2.5 to 3,
-2.5 to -2); this is an observation, not a documented guarantee, so verification accepts either neighbour.

## Native acceptance (SoX 14.4.2; new checks, not old receipts)

`tools/qualify_sox_mix.py`, own `wave` reader and `Fraction` oracle, run in two parts after the final source:
200 matrix cases (mono/stereo at 8000, 22050, 44100 and 192000 Hz, both policies, five placements, five
gain pairs; 153000 samples), 12 extreme/tie/boundary cases, 8 sweeps (every PCM16 value at five gains and
40000-pair random mixes; 447680 samples), 15 refusals before any native stage, 20 forged runs with refreshed
digests rejected, source-change invalidation and verified workflow resume, an artifact handoff, timeout and
cancellation, and both shipped examples. Every output sample, and each padded intermediate, is compared;
all 24594 observed ties went toward positive infinity. A first full run stopped at a qualifier bug (it read
the first retained workflow attempt) and an earlier one at a plan-stage refusal assertion; both repairs
are kept as evidence, and the stages were rerun.

## Completion repair (25 October 2026, local)

Two gaps in the first delivery were closed and rechecked on the final source.

- **Primary qualifier.** `tools/qualify_sox.py` sent every development case that was not `conform` or
  `normalise` to the assemble oracle, so the first unmodified run stopped with `KeyError: 'clips'` at the
  first `mix` case after the native kit had passed. It now dispatches `mix` to `qualify_sox_mix.kit_case`
  (own `wave` reader and `Fraction` oracle; captures bound to the declared source bytes, both padded
  intermediates and every output sample compared) and asserts that any other case is `assemble`; the
  assemble, conform and normalise assertions are unchanged. The complete primary run then passed on SoX
  14.4.2: all 14 development cases native-verified, assemble oracle on its five cases (1536, 14000,
  13996, 8 and 8000 samples), normalise kit checks, conform acceptance, the two mix cases
  (1200 and 1300 samples), tamper, workflow reuse, handoff, composition, ancillary-chunk, rate-boundary,
  in-flight timeout and cancellation checks. `tools/qualify_sox_mix.py` was rerun in full on the same
  source: 200 matrix cases (153000 samples), 12 extreme cases, 8 sweeps (447680 samples), 15 refusals,
  20 forged runs, invalidation, workflow, handoff, lifecycle and both shipped examples; all 24594 observed
  exact ties again went toward positive infinity. The primary run applies the normalise
  exact-rule check to the three normalise kit cases and runs the full conform acceptance; the complete
  `tools/qualify_sox_normalise.py` acceptance was not rerun, and no FLAC encoder was used, so the
  normalise-to-FLAC workflow was not rerun natively here.
- **Admission.** The operation `examples` of a capability must be documents of this route, so the
  normalise-to-FLAC chain (a `schemaxis.workflow/1` graph) was removed from the `normalise` examples. It
  remains discoverable as the workflow example: it is listed under the workflow profile references in
  `readiness.json` and the adaptor references, named in the `normalise` semantics, linked from the guide
  and kept in the `normalise` guidance. `context.example.normalise.2` now passes; admission reports
  structural completion with no required failures. This is metadata only; no framework check was changed.

New host tests cover the dispatch (exact run accepted; forged output sample, wrong source bytes and wrong
gain rejected) and the example/route metadata. No qualification receipt was registered and
`absorbedVersion` is unchanged.
