# FLAC recording labels: title, artist and description (allocation 55, 2026-10-25)

Scope: an optional `metadata` object on `schemaxis.flac/1` `encodeLossless` only, a closed set of three author-declared labels
(`title`, `artist`, `description`) stored as native Vorbis comments and proved by the host from the published bytes. This
strengthens the existing `flac` adaptor; it is not a new adaptor. `decodePCM16`, the fixed encoder, budgets, the fresh native
decode of every PCM byte and every existing refusal are unchanged. The absorbed FLAC version stays 1.5.0, no version was
advanced, nothing was registered, and the registered qualification receipt (`qualification.json`) was not touched or refreshed.

## Product judgement

The encoder used to strip every tag and `parse_flac` demanded an empty `VORBIS_COMMENT`, so a lossless archive could not say what
it was and lost its name between steps. Three bounded labels let an archive keep a human-written identity. This is a product
judgement from reading the adaptor and its workflows, not evidence of customer demand. The labels are declared text: they are not
an identity, licence, rights or provenance certificate, and a coherent rewrite of the request, the FLAC and every retained record
still verifies (semantic consistency, not authenticity). There is no independent host FLAC frame decoder.

## Design

* Document: `metadata: {title?, artist?, description?}`, at least one key, closed (unknown key: `UNKNOWN_ARGUMENT`; wrong shape or
  content: `INVALID_FLAC_METADATA` with a `$.metadata.<label>` location). `metadata` on `decodePCM16` is `UNKNOWN_ARGUMENT`.
  Everything is validated during planning, before a native process or output directory exists.
* Values: nonempty plain text with at least one letter, number, punctuation mark or symbol; no control characters (so no newlines
  or tabs), lone surrogates, line or paragraph separators, bidirectional controls, private-use or noncharacter code points or
  invisible format characters (the zero-width joiners are allowed). Limits 200/200/1000 code points and 512/512/3000 UTF-8 bytes
  (the byte limits bind for emoji and CJK). Values are stored exactly as authored: no trimming, cropping or normalisation, `=`
  and non-ASCII preserved.
* Native mapping (official FLAC 1.5.0 manual, read 2026-10-25): fixed `TITLE`, `ARTIST`, `DESCRIPTION`, one
  `--tag=FIELD=VALUE` argument per value in that fixed order, no shell, no `--tag-from-file`, no authored field name or flag.
  `--no-utf8-convert` precedes the tags (the manual says it must appear before any tag option) and is added only for a labelled
  archive. It is needed: the adaptor's native environment is `LC_ALL=C` and, observed with the real binary, omitting it turns
  `Café` into `Caf##` while exiting 0.
* Verification: the host parses the published `VORBIS_COMMENT` bytes (little-endian vendor length, vendor, entry count, each
  entry, exact block consumption) and requires exactly the authored entries, order and cardinality, a libFLAC 1.5 vendor and no
  other metadata block, then still decodes the actual FLAC bytes again natively and compares every PCM byte, the STREAMINFO MD5
  and sample count. The request, plan, capture record, summary (`metadata` record read back from the file) and result claims carry
  the mode in closed typed form. Receipt metadata is never trusted.
* Absent `metadata`: the plan, losses, native argv, launcher, capture record, FLAC bytes, summary, result and claims are
  unchanged (compared byte for byte with the pre-change adaptor below). The old empty-comment guard keeps its message.
  `decodePCM16` still drops tags and there is no tag extraction feature; WAV `LIST` and `JUNK` text is never used as labels.

## Checks run in this allocation (new, run 2026-10-25)

Host tests (no native process; `SCHEMAXIS_FLAC` unset): `test_flac`, `test_flac_native_boundary`, `test_flac_tags`: 88 tests OK,
3 skipped (the real-binary classes). With the real `flac` and its sibling `metaflac` configured the same three modules ran 88
tests OK, 0 skipped. The new `test_flac_tags.py` has 33 tests: validation matrix (about 45 refused values and key shapes,
inclusive limits in code points and bytes, exact preservation, NFC versus NFD), schema and declaration agreement, a strict
comment-reader unit matrix, a fake `flac` that reproduces the observed locale conversion, and 18 labelled-run cases including
refreshed-hash forgeries of the comment block (value, size, order, count, duplicate, extra, empty, vendor, trailing bytes,
normalisation), request and capture forgeries, summary and result forgeries, an untagged run promoted to labelled and the
reverse, launcher tampering, PCM forgery with intact labels, unreferenced files, decode of a labelled archive, and refusal
before any launch. Against the pre-change adaptor the new module fails (47 failures, 9 errors); removing the host's comment
comparison fails 11 subtests (the end-to-end forgeries were still caught by the recomputed summary and result claims, which
overlap the comparison). Not run: the full host suite, release gate and shared generators (reserved for the master integration).

Native acceptance, `tools/qualify_flac_tags.py`, final run: FLAC 1.5.0 `flac` and `metaflac` 1.5.0, 52 direct probe processes
(44 native flac/metaflac/sox, 8 `schemaxis` CLI supervisor processes; one expected non-zero exit for the invalid-label plan),
79 flac stages the adaptor started through its launcher, all exit 0. Highlights:

* ASCII, Unicode, `=`-bearing, flag-like (`--tag=EVIL=1`, `-w --force`), space-padded and NFD values and single-label subsets: the
  published comments equal hand-written literal byte strings, `metaflac --no-utf8-convert --show-tag` prints the exact values, a
  separate literal binary reader agrees, and this tool's own `flac -d` returns every PCM byte of the fixture WAV (STREAMINFO MD5
  independently recomputed). Without `--no-utf8-convert` the same title becomes `Caf##` in the C locale.
* Maximal labels (200 code points, 510 and 3000 bytes) are accepted and read back exactly; one unit over each limit is refused
  before any native process, as are empty, whitespace-only, control, surrogate, bidi, private-use and invisible values.
* Real flac files with the wrong comments (changed value, reversed order, extra tag, missing artist, duplicate, untagged,
  normalised title, locale-converted bytes, empty value, different PCM with correct labels) replace `audio.flac` with every
  receipt hash refreshed and the summary rebuilt where possible: all `VERIFICATION_FAILED`. Request and plan rewritten to claim
  labels the file lacks, and the reverse, also fail on the comment check. A coherent rewrite of every record around a valid
  FLAC with different labels and effort `-0` verifies; that is the documented semantic-consistency limit, not a defect found.
* Absent labels against the pre-change adaptor on two encode and two decode cases: the same files byte for byte (22 and 17), the
  same membership, the same receipt apart from run paths and per-run submission records, each run verified by the other
  version's code; the pre-change adaptor refuses `metadata` and its verifier refuses a labelled run. Four genuine untagged
  receipts produced by earlier native runs (three kit runs and one workflow archive) verified with the new code and by
  `schemaxis verify`, with their trees unchanged (hashes before and after in the private acceptance report).
* The documented CLI as real processes: plan, run and verify of the tag-archive example, and the invalid-label example refused.
* One actual SoX conform, labelled archive and PCM16 decode workflow: the archive carries the labels, the decoded WAV equals the
  SoX output byte for byte, the decode drops the labels, an unchanged resume reuses every job and an edited workflow is refused
  (`RESUME_MISMATCH`). No human review or quality assessment of any audio was performed or is claimed.
* Shared readiness acceptance (`qualify`) of all six cases including the new `tag-archive` and `tag-unicode` passed; its receipt
  was not registered.

## Preserved attempts

Five earlier runs of the qualifier are retained privately: three stopped on defects in the tool itself (forgery script ordering, a
receipt comparison that included per-run submission digests, a workflow edit that the framework correctly refuses to resume), one
on report formatting after the native work had passed, and one full pass before the request-forgery cases were tightened to
rewrite the capture record consistently, so that the comment check, not the capture binding, is what refuses them. The final run
above is the only one cited for the claims here.

## Limits and not claimed

Source-archive signatures were not verified; the runtime is an isolated build outside the repository. Other FLAC releases, Ogg
FLAC, other tag fields, tag editing of existing files, pictures, ReplayGain, tag extraction and any statement that a label
identifies or licenses a recording are out of scope. Unicode assignment is not checked: unassigned code points are accepted. Retained label validation uses the verifying Python's Unicode database, so a future classification change can cause a genuine labelled archive to be refused.
The host does not independently decode FLAC frame bodies. Serial, named-case evidence only; no MPI or exhaustive coverage.
