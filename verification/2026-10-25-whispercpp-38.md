# whisper.cpp allocation 38: host-only human corrections with a reviewed publishing handoff

Scope: the new separate route `schemaxis.whispercpp.correct/1` (`corrections.py`) of the whisper.cpp provider, the new closed
contract `schemaxis.timedtext.reviewed/1` in `schemaxis.core.timed_text`, and the Pandoc `transcript` block's acceptance and
provenance paragraph for a reviewed document. The transcription route `schemaxis.whispercpp/1`, its official 1.9.5 mapping and
its qualification record are unchanged and are not re-reviewed here.

## What the route does

- It captures one pinned machine `segments.json` (`basisSha256`), applies authored `{index, text}` replacements and publishes
  `reviewed-segments.json` (kind `text`, artifact index 0), `transcript.txt`, `captions.srt`, `captions.vtt`, the exact ledger
  `corrections.json` and, with `captionReview`, `caption-review.json` recomputed on the corrected text.
- `human-corrected` needs at least one changed cue; `human-reviewed-unchanged` needs none. A required note is bounded plain text.
- Timings, language, cue count and audio, model and native-JSON provenance are carried over. The draft is never modified, and a
  reviewed document is refused as a draft.
- Planning never opens the draft. Every run and verification replays the derivation from the captured bytes and authored edits and
  compares every publication byte for byte, so refreshed ordinary hashes cannot hide an altered file.

## Not claimed

- No recognition accuracy, no reviewer identity, no proof that audio was heard, no readability or accessibility certification. The
  review status is a declaration by the author of the correction document, and every publication says so.
- **No native qualification.** The route is host-only. It has no entry in `qualification.json` (untouched), readiness reports its
  `nativeQualification` and `runtimeAvailability` as `unknown`, and a transcription receipt for the provider does not qualify it.
  `adaptor conform` ran in host mode only; no `--native` conformance was run for this route.
- Not covered: timing edits, splits, merges, insertions, deletions, multiple review rounds on one document, drafts beyond 512 cues,
  256 characters per cue or 32768 in total, or other languages' accuracy.

## Repair after independent review 15 (2026-10-25)

Findings 1-6 and 8 are repaired; finding 7 stays a documented limit (`docs/whispercpp.md#human-corrections`, no retained-input hook added).

1. **Earlier Pandoc transcript runs.** Reproduced read-only against the genuine allocation-33 run `jfk-transcript-artifact`: before, `verify` failed with
   `report summary differs` (the plan was accepted, the summary was rebuilt with the new sentence). `retained_plan` now accepts the earlier sentence only
   when every captured transcript is a machine draft and replays the summary against the stored losses. Re-verification of that genuine run now passes with the
   evidence tree byte-identical before and after. A reviewed transcript carrying the earlier sentence is refused. Real Pandoc 3.12.1 also covers a rewritten
   machine run (verified), an earlier plan with a current summary (refused for the summary) and a reviewed run with the earlier sentence (refused for the wording).
2. **No person reviewed the fixtures.** Every example note and the docs now say "Illustrative example declaration; no person reviewed this recording for it."
   The qualifier's authored-note probe rewrites the note through JSON instead of searching for a word.
3. **`.dispatch`** is no longer exempt from membership; a planted `.dispatch/transcribe/replay-x.py` is refused and never run (unit test and native probe).
4. **Missing versus invalid.** A missing file or directory on the draft path is `DRAFT_SOURCE_MISSING`; links, directories, dangling links and oversize files stay
   `INVALID_DRAFT_SOURCE`. An absent `draft`, `review` or their required members is `MISSING_ARGUMENT`.
5. **Note policy.** The note refuses non-space whitespace, format controls, private use and noncharacters (cue text keeps its Unicode); Pandoc re-checks the note at
   `<block>.segments.review.note`. The Pandoc native contract is unchanged. Consumer-specific limit: a note with a zero-width joiner (for example Persian) is refused.
6. **Total budget.** The corrected total is judged on the finished cue list and refused at the `$.corrections[n].text` that adds the most, with correction-specific
   recovery. Real tests cross 32768 and show a later shrinking correction is not refused for an earlier growing one.
8. **`1e400`** is refused when parsed (`TIMED_TEXT_INVALID_JSON`, "overflows to infinity"), not later.

Evidence is under `repair-corrections-compat/` (`logs/`, `native/`). Host tests for the owned files and the other whisper.cpp and Pandoc tests: 297 OK. The
three failures in the shared set (reserved `timedtext.reviewed` document stem and workflow guidance indices) are the unchanged master hand-offs above.
