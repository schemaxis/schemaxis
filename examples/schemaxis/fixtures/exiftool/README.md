# ExifTool adaptor fixtures

Original synthetic baseline JPEG/JFIF files generated by `tools/author_exiftool_fixtures.py` from literal
specifications (the `FIXTURES` table in that tool). They contain a colour pattern of DC-only blocks, no photograph, no
camera output, no GPS fix of a real place (`river-bend.jpg` carries one synthetic GPS IFD that the adaptor must ignore)
and no third-party sample. Regenerate with `python3 tools/author_exiftool_fixtures.py NEW-EMPTY-DIRECTORY`; the bytes
are deterministic. Expected values are the literal table in the tool, not ExifTool output.

The workbench fixtures (`WORKBENCH_FIXTURES`, `SIDECARS` and `SIDECAR_PAIR` in the same tool, for example `ridge-line.jpg`, `conflict-desk.jpg`, `duplicate-tags.jpg`, `lens-record.jpg` and the `.xmp` sidecars) are generated the same way and carry EXIF, GPS, IPTC and XMP
payloads from literal tables; the committed bytes are checked against the tool by a unit test.

The repair fixtures of the same family: `padded-make.jpg` (the baseline `north-gate.jpg` with `Northfield\0` edited in place to `Northfiel \0`, same size: the independent reader keeps the trailing space and ExifTool trims it, a real native disagreement); `south-west-sea.jpg`, `zero-refs.jpg` and `default-altitude.jpg` (southern/western/below-sea references, zero coordinates that still carry references, an altitude with no reference tag); `near-zero.jpg` (rationals that ExifTool prints as `0.000125`, `2.328306437e-10`, `0` and `-4.656612875e-10`); and `mixed-sources.jpg` (a malformed EXIF capture time beside a valid XMP one).

The repeated-reference fixtures: `repeated-lat-ref.jpg` (`GPSLatitudeRef` written twice, `N` then `S`), `repeated-lon-ref.jpg` (`GPSLongitudeRef` written twice, `E` and `E`) and `repeated-alt-ref.jpg` (`GPSAltitudeRef` written twice, `0` then `1`); the rest of each GPS IFD is valid. ExifTool 13.55 lists the last copy as the main tag and the earlier one as `Copy1`.
