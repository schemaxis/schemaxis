# Schemaxis demonstrations

A guided set of cross-application demonstrations. Configure paths for your machine
using the [CFD guide](../../docs/cfd-guide.md) before running. For the commands
alone, see [QUICK-START.md](QUICK-START.md). This pack uses the registered
application adaptors.

## Start here

Open a **normal terminal**, then paste:

```bash
cd /absolute/path/to/schemaxis
python3 examples/demos/demo.py doctor
```

Configure only the applications needed by your chosen demo using the helper's
`--APP` options or `SCHEMAXIS_DEMO_APP` environment variables (see `--help`).
Use `doctor vehicle` for ParaView and the configured case, or `doctor pipe` for
the CAD/render/video stack. Plain `doctor` checks all demo dependencies. Paths
shown below are placeholders; console commands require your actual absolute paths.
No local runtime wrappers or prior evidence are required. Keep the terminal at
the repository root.

The simplest command pattern is:

```bash
python3 examples/demos/demo.py run pipe
python3 examples/demos/demo.py show pipe
```

`run` builds the workflow input, executes the native applications, and then runs
`schemaxis verify`. It creates a NEW dated directory under `evidence/demos` every
time. `show` opens an HTML gallery of the latest **successful** run in your default
browser. Earlier runs are retained. A failed run does not replace the latest
successful result. Read the run path printed by the command; the full native output
is in `run.log`, and the independent offline verification is in `verify.log`.

The gallery is a local file, not a hosted website. Its media must stay beside it.
For native editable output, use `open` as shown below. Close native app windows
normally when finished. Do not edit a verified output in place before demonstrating
verification; use Save As if you want to experiment with it.

## Suggested tour

| Step | Action | What it shows |
| --- | --- | --- |
| 1 | Open `pipe.input.json`; look at `dimensions` | Physical inputs are central and downstream geometry refers to them. |
| 2 | Web console: preview, change bend radius, preview, undo | Humans can edit and inspect actual native CAD. |
| 3 | Pipe movie and FreeCAD/Blender outputs | One input feeds several applications and retains editable artifacts. |
| 4 | Vehicle slices, seed sweep and iso-surface orbit | One repeatable description produces the scientific views. |
| 5 | Fine/coarse mesh inspection and numerical output | Handoffs support engineering inspection as well as presentation. |
| 6 | QGIS → Godot; optionally sprite → Godot/video | The same mechanism works across different application families. |

Rendering can take minutes, so generate results before showing them, then use
`show` and `open`. Run durations vary with the machine and its load.

## 1. Web console: pipe-bend geometry

### Launch and connect

In the terminal:

```bash
python3 examples/demos/demo.py console
```

The terminal prints a line beginning **Visual console: http://127.0.0.1:...**.
Copy the **entire URL, including `?token=...`**, into Chrome/Firefox or the Codex
browser. Keep the terminal running. The port and token change on each launch.
The helper creates a fresh workspace per launch, so each session starts clean.
To recover an earlier workspace, use the raw CLI command below with its saved path.

The page has two different inputs:

- **Command console**, near the bottom: executable declared commands go here.
- **Compose a request**: saves prose and picked geometry references. It does **not**
  execute a natural-language simulation request.

Use a full-width browser window. Scroll to **Command console**. Paste ONE line at
  a time and click **Run** (or press Enter). Wait for the command to finish before
  submitting the next. Do not paste the entire command sheet at once.

### Load the model

```text
open /absolute/path/to/schemaxis/examples/demos/pipe.input.json
live /absolute/bin/freecad
preview
```

After `preview`, the geometry pane should show a hollow 90-degree elbow. The
sidebar lists native faces, edges and vertices. An image preview also appears.
The initial preview has 4 faces, 6 edges and 4 vertices; tessellation counts can
change with dimensions and mesh deflection.

The browser is displaying geometry generated by FreeCAD. This is the same
input that the batch workflow uses.

Drag to orbit, scroll to zoom, use **Fit** or **Isometric** if you lose the model.
Choose **Section → Z** and move the slider to expose the bore; return Section to
**Off** afterwards. These are view controls and do not modify the CAD model.

### Make a dimensional edit

The initial bend radius is 60 mm. Change it to 80 mm:

```text
set document dimensions '{"bendRadius":80,"outerRadius":18,"innerRadius":14,"bendAngle":90,"meshDeflection":0.05}'
preview
```

`set document dimensions` replaces the complete dimensions object, which is why
all five entries appear here. Both outer and inner profiles move from that one
shared radius. The outer wall and the bore remain linked to the same design
parameter.

Undo and preview again:

```text
undo
preview
```

Optional: click a face, then write a request containing that reference in the
composer. This records precise intent for the current revision; it does not
execute arbitrary prose. References become stale after a geometry edit.

### Save and stop

```text
save /absolute/path/to/schemaxis/evidence/demos/practice-pipe.FCStd
save /absolute/path/to/schemaxis/evidence/demos/practice-pipe.json
```

Use another basename if those files already exist. The console protects existing
save destinations. Saving JSON records the authored inputs; saving FCStd requires
a successful current native preview. Session edits do not change the original
`examples/demos/pipe.input.json`.

When finished:

```text
unload
```

Then press **Ctrl+C in the terminal that launched the server**. The URL stops
working. The console workspace and history remain on disk.

Raw CLI equivalent, useful to reopen a saved workspace:

```bash
PYTHONPATH=src python3 -m schemaxis console --provider freecad \
  --workspace /absolute/path/to/the/saved/console-workspace --web
```

The copy/paste command sheet is `console-commands.txt`.

## 2. FreeCAD → Blender → FFmpeg

### Run and open

```bash
python3 examples/demos/demo.py plan pipe
python3 examples/demos/demo.py run pipe
python3 examples/demos/demo.py show pipe
python3 examples/demos/demo.py open pipe --app video
python3 examples/demos/demo.py open pipe --app freecad
python3 examples/demos/demo.py open pipe --app blender
```

Each `open` command starts the selected application. You do not have to open all
three simultaneously. The normal run produces:

- Editable `model.FCStd`, STEP and STL from FreeCAD.
- 24 orbit PNGs, a saved `.blend` and a checked STL from Blender.
- A three-second MP4 at 8 fps. Use loop playback.

Open `pipe.input.json` in your editor. The `dimensions` object contains radii,
angle and meshing deflection; feature options reference those values. Change
`bendRadius` from 60 to 80, save the file, then rerun `run pipe`. Restore 60 and save
when finished if you want the original geometry. Keep `innerRadius < outerRadius <
bendRadius`; this is an illustrative elbow, not a pressure-rated design.

`presentation.json` controls `orbitFrames` and `fps`. Use 24 frames for a first run;
48 at 12 fps produces a smoother four-second orbit and takes longer. Keep frame
count modest: decoded video inputs have a 192 MiB adaptor budget.

CAD dimensions are in millimetres. The Blender import explicitly converts
them to metres. Both native documents are retained and the published files verified.

## 3. FreeCAD → Blender → ParaView: mesh inspection

```bash
python3 examples/demos/demo.py run inspection
python3 examples/demos/demo.py show inspection
python3 examples/demos/demo.py paths inspection
```

This uses the same pipe CAD input. Two Blender branches bake the mm-to-m scale,
then voxel-remesh at 1.5 mm and 4 mm. ParaView reads each resulting STL, exports the
mesh and a mid-plane section, and writes a CSV containing integrated surface-area
information. The gallery has corresponding scientific-output links.

Show the fine and coarse images. Open the two measurement CSVs listed by `paths`
in an editor. The Area value is square metres; this measures the remeshed surface,
not CFD solution accuracy. The 4 mm grid is intentionally coarse relative to the
4 mm wall and may erase detail. This comparison is the point of the example.

The geometry can be inspected and measured after an application handoff.

To change the two mesh resolutions, edit the `fine`/`coarse` values in the
`inspection` branch of `demo.py`; they are in metres. CAD dimensions stay in the
human input. The full generated workflow is inspectable with `export inspection`.

## 4. Vehicle and wake: ParaView → images → FFmpeg

```bash
python3 examples/demos/demo.py run vehicle
python3 examples/demos/demo.py movies vehicle
python3 examples/demos/demo.py show vehicle
```

The input is `vehicle.input.json`. Set `--case /absolute/case/case.foam` or
`SCHEMAXIS_DEMO_CASE`; the original coupe case is not included in this repository.
Adapt bounds, field names and patch groups to your case.
The latest available time is discovered natively.
No CFD solver runs or changes to this source case are made.

Show these four areas in the input:

1. `dimensions`: measured vehicle bounds, ground and seed geometry.
2. `views`: derived vehicle-and-wake bounds, expressed as multiples of vehicle size.
3. `settings`: fields, ranges, counts, case path and actual patch names.
4. `nodes`/`scenes`: the reusable processing and publication definitions.

The supplied settings generate:

- Three positions along each X/Y/Z slice sweep, with pressure and speed appearances.
- Twelve orbit views of the vehicle and pressure iso-surface, framed with the wake.
- Three seed-height visits for the streamline sweep, with vehicle context.
- Verified streamline geometry exports in addition to images.

The slice cameras frame the region without cropping the original data. The complete
vehicle and wake are retained, so some endpoint slices show mostly uniform flow.
The middle Y slice is the useful introductory view. `sliceCount` can be increased
to 9 after the first run. The streamline seed heights live under
`dimensions.stream.sweepZ`; adjust those rather than editing downstream nodes.

`movies vehicle` groups images by scene and appearance, retaining receipt order
rather than alphabetic filename order. Each still is held for four frames at
8 fps. It creates a separate movie for each sweep/appearance/orbit. There is no
motion interpolation and the streamline movie sweeps seeds at one solution time.

Pressure is the stored `p` field; its physical units are not inferred. The contour
uses cell-to-point interpolation. Fixed colour ranges are display choices and are
kept consistent across comparable views. This workflow verifies outputs, not the
underlying CFD solution.

## 5. Local-region study and wing-mirror template

```bash
python3 examples/demos/demo.py run region
python3 examples/demos/demo.py movies region
python3 examples/demos/demo.py show region
```

**The coupe case these inputs were prepared for has no identified wing mirror.**
Its body is simplified. Therefore `region` is explicitly a configurable side-region
study, not a measurement of a real mirror.

`mirror.input.json` is ready to adapt once a mirror-equipped case is available.
Its central `dimensions.mirror.min/max` currently defines an illustrative side box.
`views.mirrorOne` and `mirrorTwo` expand it by one and two original extents on each
side. This means adding one/two lengths in X, widths in Y and heights in Z, not
setting total box size to one/two extents. The coordinate frame is the case's XYZ.

The study includes X/Y/Z centre slices at both framing sizes, two local seed-height
visits per view, six iso-surface orbit views at each size, and a velocity line
sample downstream, offset outward by one box width to stay in valid fluid in this case. The input includes a status label explaining
the provisional region. Sampling retains only the requested velocity arrays.

For a real mirror:

1. Set `settings.case` and the actual body/tyre patch groups for that case.
2. Enter measured mirror bounds in `dimensions.mirror`.
3. Check seed positions, sampling line, axes and fields against that geometry.
4. Set `settings.mirrorBoundsConfirmed` to `true`.
5. Run `python3 examples/demos/demo.py run mirror` and inspect the outputs.

`run mirror` deliberately stops until that confirmation is in the input. Do not
flip it merely to bypass the warning. Use `region` if no mirror case is
available. It demonstrates the same dimension-relative area-of-interest logic.

## 6. CFD results → ParaView → Blender → FFmpeg

```bash
python3 examples/demos/demo.py run cfd-render
python3 examples/demos/demo.py show cfd-render
python3 examples/demos/demo.py open cfd-render --app video
python3 examples/demos/demo.py open cfd-render --app blender
```

This uses the vehicle input's latest-time pressure contour and extracted vehicle
surface. ParaView exports two glTF geometry artifacts. Blender imports them,
restores the qualified Z-up engineering axes with an explicit -90 degree X rotation,
assigns separate presentation materials, renders the camera orbit and saves its
scene; FFmpeg encodes the frames.

The scientific extraction happens in ParaView. The next application turns
those geometry artifacts into a presentation, while the original scientific
outputs remain available.

The Blender material colours are illustrative. glTF is a geometry/presentation
handoff, not a lossless transfer of all CFD arrays or an inferred unit conversion.

## 7. QGIS → Godot

```bash
python3 examples/demos/demo.py run site
python3 examples/demos/demo.py show site
python3 examples/demos/demo.py open site --app godot
```

`site.input.json` centralises a 60 m buffer distance and a study rectangle. The
GeoJSON has **synthetic demonstration coordinates**, explicitly in projected
EPSG:32614 metres. These are not surveyed locations.

QGIS buffers and clips the features, saves a GeoPackage and editable project, and
renders a map. Godot receives that PNG as a flat image panel in an editable 3D
project. Drag with the left mouse button to orbit, scroll to zoom, and R to reset.
Close the game window when finished. This is a map-panel bridge, not generated
terrain or building geometry.

Change `dimensions.bufferDistance` to 90 and rerun for an obvious comparison.
Use `paths site` to locate the `.qgz`/`.gpkg` if you want to open them in your
separately installed QGIS GUI; the automated runtime uses QGIS Python.

## 8. Aseprite → Godot + FFmpeg

```bash
python3 examples/demos/demo.py run sprite
python3 examples/demos/demo.py show sprite
python3 examples/demos/demo.py open sprite --app godot
python3 examples/demos/demo.py open sprite --app video
```

This intentionally small, two-frame pixel-art example creates an editable Aseprite
file, a sprite sheet and timing metadata. One branch embeds the sheet in Godot;
the other makes a lossless FFV1 video and a convenient H.264 MP4. The video is short
(0.32 seconds); use loop playback. The Godot panel displays the sheet statically,
not animated sprite playback. The point is one producer feeding two consumers.

For a longer example, edit the two frame durations in `sprite.input.json` while
keeping them multiples of 40 ms (25 fps). Regenerate before showing it.

## Raw CLI commands and generated inputs

The helper is convenience orchestration. To expose a complete workflow JSON:

```bash
python3 examples/demos/demo.py export pipe
```

Then the exact underlying CLI route is:

```bash
mkdir -p evidence/demos
demo_output="evidence/demos/manual-pipe-$(date +%Y%m%d-%H%M%S)"
PYTHONPATH=src python3 -m schemaxis run evidence/demos/inputs/pipe.json \
  --freecad /absolute/bin/freecadcmd \
  --blender /absolute/bin/blender \
  --ffmpeg /absolute/bin/ffmpeg \
  --output-directory "$demo_output" --timeout 600
PYTHONPATH=src python3 -m schemaxis verify "$demo_output"
```

For standalone vehicle input:

```bash
demo_output="evidence/demos/manual-vehicle-$(date +%Y%m%d-%H%M%S)"
python3 examples/demos/demo.py export vehicle  # uses configured --case/environment
PYTHONPATH=src python3 -m schemaxis run evidence/demos/inputs/vehicle.json \
  --paraview-root /absolute/ParaView \
  --output-directory "$demo_output" --timeout 600
PYTHONPATH=src python3 -m schemaxis verify "$demo_output"
```

All helper runs print their exact expanded CLI command and retain the exact input.
`plan` uses time 1.0 only as a planning placeholder for CFD inputs whose native latest
time cannot be discovered during pure planning. `run` uses the original latest-time
selector. `export` preserves it too.

## Troubleshooting

| What happens | What to do |
| --- | --- |
| Console page does not connect | Check the server terminal is still running; use its complete current URL/token. |
| Native elements are missing | Submit `live .../freecad`, then `preview`; configuring batch execution alone does not populate the live geometry pane. |
| Old geometry remains after an edit | Wait for the edit, submit `preview`, then Fit. Picking is disabled for the stale revision. |
| Model vanishes in the viewer | Section Off, Fit, Isometric. |
| A console save says OUTPUT_EXISTS | Choose a new basename; earlier output is protected. |
| A native run fails | Read its printed `run.log`; failed evidence is retained. Fix the input and rerun into a new folder. |
| The latest gallery looks unchanged after failure | `show` deliberately keeps the previous successful run. Check the dated folder in its title. |
| Rendering takes too long | Use a prepared gallery/movie. Reduce the `presentation.json` frame count. |
| Video will not play in the browser | Use `open ... --app video` to open the MP4 in the desktop handler, or show the PNG frames. FFV1/MKV is an archival alternative. |
| Mirror command stops | Use `region` unless you have identified actual mirror geometry and supplied its bounds. |

To inspect retained paths or recheck a finished run:

```bash
python3 examples/demos/demo.py paths pipe
python3 examples/demos/demo.py verify pipe
```

No workflow in this pack launches a solver, submits cluster jobs, publishes
anything externally, or pushes Git changes.
